## 摘要
多阶段系统中的第一阶段推荐器会生成一个排序后的候选列表，其中仅有有限的前缀会被传递至下游排序器。由于每个被传递的条目都必须经过成本更高的排序阶段处理，因此该候选短名单不能任意扩大。第一阶段的目标因此是在被传递的前缀中实现对相关条目的高覆盖率，通常由 Recall@k 衡量。一个相关条目可能出现在检索列表的更靠后位置，却不在实际被消费的较短前缀中。本文研究事后验证，以在不重新训练或替换检索器的情况下，将此类候选提升到被消费的短名单中。我们为检索模型引入了一个轻量级生成式验证器。给定检索器状态和一个候选条目，验证器通过其标识符 token 的似然来对该条目进行评分。它采用下一 token 交叉熵进行事后训练，训练时不需要采样负例或候选池，并且在推理时仅对检索器的 top-K 候选进行评分。其接口非常简洁：检索器提供查询状态和候选条目，而条目表示可以使用任意固定的分词方式。在 Amazon 商品推荐和 YaMBDa 音乐推荐上，相同的验证器训练方案提升了 SASRec、GRU4Rec、NextItNet 和 MiniOneRec 的 Recall@10。消融实验表明，这些提升不能仅由向检索器注入条目内容特征来解释，从而支持将验证作为一种事后输出侧适配机制。

## Abstract
First-stage recommenders in multi-stage systems produce a ranked candidate list from which a limited prefix is forwarded to downstream rankers. Because each forwarded item must be processed by more expensive ranking stages, this shortlist cannot be arbitrarily large. The first-stage objective is therefore high coverage of relevant items within the forwarded prefix, commonly measured by Recall@$k$. A relevant item may be available deeper in the retrieved list but absent from the shorter prefix that is actually consumed. This paper studies post-hoc verification for promoting such candidates into the consumed shortlist without retraining or replacing the retriever.   We introduce a lightweight generative verifier for retrieval models. Given a retriever state and a candidate item, the verifier scores the item through the likelihood of its identifier tokens. It is trained post hoc with next-token cross entropy, requires no sampled negatives or candidate pool during training, and scores only the retriever's top-$K$ candidates at inference. The interface is minimal: the retriever supplies a query state and candidate items, and the item representation can use any fixed tokenization.   Across Amazon product recommendation and YaMBDa music recommendation, the same verifier training recipe improves Recall@10 for SASRec, GRU4Rec, NextItNet, and MiniOneRec. Ablations show that the improvements are not explained solely by injecting item-content features into the retriever, supporting verification as a post-hoc output-side adaptation mechanism.

# 论文总结：Recommendation Retrievers Need Verifiers

## 1. 核心问题与整体含义

- **研究背景**：多阶段推荐系统通常由第一阶段检索器从大规模物品库中生成排序候选列表，但只有有限前缀会被送入下游更昂贵的排序阶段。因此，第一阶段的关键目标是在有限短名单中尽可能覆盖相关物品，常用 **Recall@k** 衡量。
- **核心问题**：相关物品可能已出现在检索器较深的 top-K 列表中，但未进入实际被消费的较短前缀，导致 Recall@k 受限。扩大前缀又会增加下游排序成本。
- **整体含义**：论文提出一种**事后验证机制**，在不重新训练、不替换检索器、不重建索引的前提下，把检索器 top-K 池中“排名偏后但可能相关”的物品提升到被消费短名单中。
- **类比与区别**：方法受语言模型“草稿—验证”解码启发：冻结的检索器相当于 drafter，轻量 verifier 对候选打分。但与 speculative decoding 不同，目标不是保持采样分布，而是提升推荐召回覆盖率。

## 2. 方法论

- **核心思想**：
  - 冻结第一阶段检索器/ drafter，仅训练一个轻量级生成式 verifier。
  - verifier 以 drafter 的查询状态为条件，对候选物品的离散标识 token 序列做自回归似然评分。
  - 推理时只重排 drafter 的 top-K 候选池，并用 rank fusion 与原始检索分数融合。
- **接口设计**：
  - drafter 提供：查询/用户历史对应的状态 \(d_t\)，以及 top-K 候选池 \(P\)。
  - 物品表示：任意固定 tokenization \(\tau(j)\)，如原始 ID、PQ 码、semantic ID、hash token 或拼接。
  - 实验实例：4 级残差量化 semantic ID（每级 256 项）+ 4 头乘法 hash ID（每头 1024 桶）。
- **条件向量**：
  - 通过线性投影桥接 drafter 与 verifier 的维度：
    \[
    c_t = W_{\text{proj}}\,\text{sg}[d_t]
    \]
  - 其中 \(\text{sg}[\cdot]\) 为 stop-gradient，阻断梯度回传到冻结的 drafter。
- **verifier 结构**：
  - 小型因果 Transformer，实验中使用 2 层、2 头、宽度 128。
  - 对候选物品自身的标识 token 序列建模，而非重新建模用户历史。
  - 条件向量 \(c_t\) 加到每个 token 位置，按因果掩码预测下一个 token。
- **评分函数**：
  - 候选 \(j\) 的 verifier 分数为其 token 序列自回归对数似然：
    \[
    s_2(j|x_{1:t}) = \sum_{\ell=1}^{L}\log p_\phi(y^j_\ell \mid c_t, y^j_{1:\ell-1})
    \]
- **训练方式**：
  - 使用 teacher forcing 的下一 token 交叉熵。
  - 对每个非 pad 前缀位置都提供监督，损失为：
    \[
    L(\phi, W_{\text{proj}}) = -\sum_u \sum_t s_2(x^u_{t+1})
    \]
  - 训练不需要采样负例、不需要 in-batch negatives，也不需要候选池。
  - 对比 InfoNCE 等对比学习，避免 batch size / 候选池大小对学习信号的敏感性。
- **推理流程**：
  - drafter 生成 top-K 池 \(P\)。
  - verifier 对池中每个候选计算 \(s_2\)。
  - 使用加权 Reciprocal Rank Fusion：
    \[
    \text{RRF}(j)=\frac{1}{\kappa+\text{rank}_1(j)}+\frac{w}{\kappa+\text{rank}_2(j)}
    \]
    其中 \(\kappa=60\)，\(w\) 为验证器权重，由验证集选择。
  - 融合后对 \(P\) 重排，随后按 drafter 原始 \(s_1\) 顺序回填池外物品。

## 3. 实验设计

- **数据集 / 场景**：
  - **Amazon Reviews 2018**：Industrial & Scientific 与 Office Products 两个域，使用 MiniOneRec 仓库发布的预处理数据。
  - **YaMBDa**：匿名音频/音乐推荐基准，三个交互规模：50M、500M、5B；物品目录从 0.63M 增至 5.36M。
- **评估指标与候选池**：
  - Amazon：Recall@3/5/10，verifier 重排 top-100 池。
  - YaMBDa：Recall@10、Recall@100，verifier 重排 top-1000 池；Recall@1000 按构造保持不变，未报告。
- **Drafters / 对比对象**：
  - SASRec：自注意力序列推荐。
  - GRU4Rec：门控循环序列推荐。
  - NextItNet：膨胀因果卷积序列推荐。
  - MiniOneRec：LLM 生成式 semantic-ID 推荐器，使用发布 checkpoint，仅用于 Amazon 文本数据。
  - 主要对比为各 drafter **stand-alone** 与 **+Verifier**；部分结果与 MiniOneRec / YaMBDa 论文已发表值括号对比。
- **训练配置**：
  - 三个序列 drafter 均用 in-batch InfoNCE 训练。
  - verifier 在冻结 drafter 状态上事后训练。
  - 随机种子统一为 42；融合权重在验证集上选择。
- **消融与分析实验**：
  - 融合权重 \(w\) 扫描：YaMBDa-500M，三个 drafter，从 0 到过加权区间。
  - Drafter 规模扫描：隐藏维度 64/128/256/512、深度 2/4、历史长度 100/200/400，共 24 配置/家族，三个家族共 72 配置。
  - Identifier 通道消融：semantic-only、hash-only、semantic+hash，在 YaMBDa-500M 与 Amazon 上进行。
  - 内容控制实验：ID-only、ID+semantic-code content、semantic-code-only，用于区分“输出侧验证”与“内容特征注入”。
  - 目标类型分析：YaMBDa-500M 上区分 re-listen 与 never-heard 目标。
