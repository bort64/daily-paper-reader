## 摘要
生成式推荐（GR）依赖大束宽解码来生成数百个候选物品，这为循环线性注意力带来了新的扩展挑战。现有的线性注意力服务系统要么为每个束具体化完整的循环状态，要么反复重放共享历史，导致巨大的内存和流量开销。为解决这一问题，我们提出 OneLA，一个线性注意力解码框架，它利用 GR 工作负载中共享的提示以及较短的分歧后缀。具体而言，OneLA 使用单个由提示导出的共享状态以及各束分叉转移的紧凑、仅追加记录来表示所有束状态。利用这种表示，OneLA 仅计算每个解码步骤所需的状态信息，而无需为每个束重建完整的循环状态。此外，OneLA 使用轻量级祖先索引来跟踪构成每个束历史的转移记录，使束能够在不移动或复制现有记录的情况下更新。一个融合的 GPU 内核进一步在各束之间复用共享状态。我们的分析表明，OneLA 实现了 1.54-2.46 倍的端到端解码加速，同时大幅降低了循环状态的内存占用和数据移动。

## Abstract
Generative recommendation (GR) relies on large-beam decoding to generate hundreds of candidate items, creating a new scaling challenge for recurrent linear attention. Existing linear attention serving systems either materialize a full recurrent state for every beam or repeatedly replay shared history, incurring substantial memory and traffic overhead. To address this, we present OneLA, a linear-attention decoding framework that exploits the shared prompt and short divergent suffixes of GR workloads. Specifically, OneLA represents all beam states using a single shared prompt-derived state and compact, append-only records of their divergent transitions. Using this representation, OneLA computes only the state information required at each decoding step, without reconstructing a full recurrent state for every beam. Furthermore, OneLA uses a lightweight ancestry index to track the transition records that make up each beam's history, allowing beams to be updated without moving or copying existing records. A fused GPU kernel further reuses the shared state across beams. Our analysis shows that OneLA achieves 1.54-2.46x end-to-end decode speedups while substantially reducing recurrent-state memory use and data movement.

## 1. 核心问题与整体含义

- **研究背景**：生成式推荐（GR）通常将物品表示为离散语义 ID（SID）序列，并把推荐转化为自回归序列生成。与普通 LLM 服务不同，GR 需要一次性生成数百个候选物品，因此依赖**大束宽解码**：每步扩展所有活跃 beam，再全局选择 top-k 候选。
- **核心矛盾**：GR 的 prompt 很长、生成后缀较短、beam 宽度很大且动态演化。线性注意力（如 Gated DeltaNet, GDN）用固定大小循环状态压缩历史，缓解了长上下文计算和 KV 存储问题；但大束宽使“每个 beam 一个循环状态”成为新的扩展瓶颈。
- **现有系统不足**：
  - vLLM FullState：为每个 live beam 物化完整循环状态，显存和读写流量随 beam 宽度急剧增长。
  - vLLM ReplaySSM：通过前缀重放减少状态持久化，但不区分长共享 prompt 与短解码阶段，可能在解码时重放较长 prompt tail；且把每个 beam 当独立请求，需单独加载缓存并重放。
  - SGLang、FlashInfer、TensorRT-LLM：更多是算子级支持，缺少端到端 GDN beam search 服务能力。
- **关键洞察**：同一请求内所有 beam 都来自相同的 prompt 后循环状态，只在短解码阶段发生分歧；GDN 转移可由紧凑记录表示；beam 选择只改变引用关系，不修改历史记录。因此可以避免为每个 beam 物化完整循环状态。

## 2. 方法论：核心思想与关键技术

- **总体思想**：OneLA 将每个 beam 的状态表示为：
  - 一个请求级共享的 post-prefill 循环状态 \(S_{\text{ctx}}\)；
  - 一串紧凑、仅追加的 GDN Transition Records（GTR）；
  - 一个轻量祖先索引，用于追踪每个逻辑 beam 对应哪些 GTR。
- **GDN 转移与 GTR**：
  - GDN 更新可写为  
    \(S_t = \alpha_t S_{t-1} + \delta_t k_t^\top\)，其中  
    \(\delta_t = \beta_t (v_t - \alpha_t S_{t-1} k_t)\)。
  - OneLA 将一次转移记录为 \(r_t = (\alpha_t, \delta_t, k_t)\)，即 GTR。
  - 每个 GTR 只需 \(O(d_v + d_k)\) 存储，而不是完整状态矩阵的 \(O(d_v d_k)\)。
  - 存储 \(\delta_t\) 而非 \((\beta_t, v_t)\)，因为 replay 只需要状态投影，不需要重建完整状态矩阵。
