## 摘要
工业推荐排序模型已分别扩展了特征交互与序列建模；近期架构如HyFormer和MixFormer通过可堆叠骨干统一了两者。然而，现实世界的推荐系统几乎总是需要多任务学习，但现有统一架构将多任务建模限制在浅层骨干后塔中，使骨干缺乏任务感知的信息流。我们提出MORE（多任务协同演化排序模型），将多任务信息流嵌入骨干内部，使任务特定信号能在每一层与序列和特征表示协同演化，而非事后融合。它引入了跨骨干层持久存在的锚点令牌：共享锚点编码跨任务共性，而私有锚点捕获任务特定先验。在每个块中，锚点令牌（1）从行为序列读取任务条件信号，（2）在任务边界掩码下与非序列特征混合，（3）通过独立分支细化每任务表示；随着块的堆叠，每个任务获得经所有骨干层细化的差异化表示。在大规模工业数据集上的实验表明，MORE在可比参数和FLOPs预算下始终优于所有任务的基线，并能随模型规模良好扩展。在中国领先的社交发现平台陌陌（拥有数千万月活跃用户）上的在线A/B测试显示，使用时长提升3%，互动率提升3.6%，深度聊天率提升2%。MORE已投入生产，通过请求级共享计算将评分延迟降低约30%。

## Abstract
Industrial ranking models for recommendation have scaled feature interaction and sequence modeling separately; recent architectures such as HyFormer and MixFormer unify both in a stackable backbone. Real-world recommender systems, however, nearly always require multi-task learning, yet existing unified architectures confine multi-task modeling to shallow post-backbone towers, leaving the backbone without task-aware information flow. We propose MORE (Multi-task cO-evolving Ranking modEl), which embeds multi-task information flow inside the backbone, enabling task-specific signals to co-evolve with sequence and feature representations at every layer rather than in a post-hoc fusion. It introduces Anchor Tokens that persist across backbone layers: Shared Anchors encode cross-task commonalities, while Private Anchors capture task-specific priors. In each block, Anchor Tokens (1) read task-conditioned signals from behavior sequences, (2) mix with non-sequential features under a task-boundary mask, and (3) refine per-task representations through independent branches; as blocks stack, each task obtains a differentiated representation refined through all backbone layers.   Experiments on large-scale industrial datasets show that MORE consistently outperforms baselines across all tasks under comparable parameter and FLOPs budgets, and scales well with model size. Online A/B tests on Momo, a leading Chinese social discovery platform with tens of millions of monthly active users, yield 3% improvement in usage duration, 3.6% in interaction rate, and 2% in deep-chat rate. MORE is deployed in production with request-level shared computation reducing scoring latency by about 30%.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **研究背景**：工业推荐排序模型近年沿着两条独立路线演进：一是特征交互的规模化（如 Wukong、RankMixer），二是行为序列建模的规模化（如 HSTU、LONGER）。近期出现统一骨干架构（如 HyFormer、MixFormer、OneTrans），将序列建模与特征交互放进同一可堆叠骨干中，解决了两类信号割裂的问题。
- **核心问题**：这些统一骨干虽然打通了序列与特征的交互，但多任务学习仍被限定在骨干之后的浅层预测塔中，骨干本身是完全“任务无关”（task-agnostic）的。也就是说，任务信号只在最终头部注入，无法影响骨干内部的信息组织方式。
- **论文指出的三个具体局限**：
  1. **任务盲读序列与盲做特征交互**：序列读取和特征交互无法按任务差异化，例如点击率依赖曝光新颖性、评论率依赖内容深度，共享查询会混为一谈。
  2. **任务分化前存在结构性瓶颈**：所有任务共享同一骨干输出，任务差异必须在压缩后的统一语义空间上进行；MMoE/PLE 等门控只能在固定基向量上重新加权，无法重建骨干中从未形成的任务感知特征组织。
  3. **规模扩展的多任务收益递减**：增加参数主要扩展任务无关的共享容量，任务无关骨干将参数增长转化为多任务 GAUC 提升的效率明显低于任务感知架构。
- **整体含义**：论文主张将多任务信息流“内嵌”到骨干各层，使任务信号与序列、特征表示在每一层协同演化，而非事后融合，从而突破上述结构性瓶颈。

## 2. 论文提出的方法论

### 2.1 核心思想
- 提出 **MORE（Multi-task cO-evolving Ranking modEl）**，一种任务感知的统一排序骨干。
- 引入 **Anchor Tokens（锚点令牌）** 作为跨层的任务感知信息载体：
  - **Shared Anchors（共享锚点）**：编码跨任务共性语义；
  - **Private Anchors（私有锚点）**：每个任务一个，捕获任务特定先验。
- Anchor Tokens 贯穿所有骨干层，在每一块中经历“读取序列 → 语义混合 → 任务增强”三步，使多任务建模成为骨干内部的连续信息流。

### 2.2 输入表示
- **任务感知多行为序列编码**：对用户历史行为采用笛卡尔积编码——每个物品与其行为组合 ID 一同嵌入，形成序列 token：  
  `s_n = e_item(i_n) + e_action(cid_n) + e_time`，从而区分不同行为类型组合，缓解跨任务梯度冲突。
- **非序列语义令牌**：用户画像、候选属性、上下文特征嵌入聚合为矩阵 `F ∈ R^{M×d}`。
- **Anchor Token 构造**：将序列池化向量与非序列扁平化语义拼接，经 MLP 投影切分为 K 个 Shared Anchors 和 T 个 Private Anchors，并为每个私有锚点添加可学习的任务先验嵌入 `π_t`。

### 2.3 MORE Block（每层的三个子模块）
1. **Task-Aware Sequence Reading（任务感知序列读取）**：
   - 对行为序列做 SwiGLU 变换并计算 K/V 记忆；
   - 维护序列寄存器 `η`，以跨层累积压缩序列摘要；
   - Shared Anchors 和 Private Anchors 通过各自独立注意力查询序列记忆，并用独立 SwiGLU 门控读取寄存器，使不同任务从同一行为历史中提取差异化信号。
2. **Selective Semantic Mixing（选择性语义混合）**：
   - 将 F、Shared Anchors、Private Anchors 拼接为统一矩阵 G；
   - 采用类似 RankMixer 的头-令牌转置机制进行轻量交互；
   - 引入 **任务边界掩码（task-boundary mask）**：F 与共享锚点对所有令牌可见，每个 Private Anchor 仅对自身可见，私有关键信息在混合过程中互不泄露、避免语义污染；
   - 经两层逐令牌 FFN 与残差连接完成全局语义融合后，再按原位置拆分。
3. **Task Enhancing（任务增强）**：
   - 借鉴 FiLM 机制，为每个任务使用独立 MLP 从非序列特征 F 生成调制参数 `(λ_t, γ_t)`；
   - 对对应 Private Anchor 做仿射调制并残差连接，提升任务特定表示的语义区分度。

### 2.4 层堆叠与输出
- 多层 MORE Blocks 顺序堆叠，循环更新共享序列状态、非序列令牌、Shared/Private Anchors。
- 最终每个任务塔接收对应的 Private Anchor，同时引入 F 与 Shared Anchors 的全局跨任务语义，兼顾共享与任务特有信息。

### 2.5 请求级共享计算（工业部署）
- 借鉴 HSTU 的请求级组织方式：同一请求下的多个候选合并为单样本，用户侧序列只编码一次；推理时将候选切分到 mini-batch 内共享用户侧计算。
- 由于序列状态是用户级共享状态、不依赖候选信息，该优化无需改动模型结构，在线评分延迟可降低约 30%。

## 6. 论文的主要结论与发现

- 将多任务信息流嵌入骨干内部，能够明显改善统一排序模型的多任务效果，骨干任务盲区是可被有效填补的结构性问题。
- 离线实验中，MORE 在全部 7 个核心任务上均取得最佳 GAUC：
  - 如 Greet +1.58%、Like +1.47%、Comment +1.26%、Deep Chat +0.33%；
  - 在互动/社交类任务上的增益尤为明显，说明这些任务对任务感知的序列读取要求更高。
- 在效率方面，MORE 参数约 132M（低于 HyFormer 的 153M），每样本 FLOPs 1.85G，低于参考基线的 1.92G，也低于 STCA、HyFormer、MixFormer；相对 OneTrans 仅多出 0.12G FLOPs。
- 扩展性研究显示，在 0.1B 至 0.9B 参数范围内，MORE 相比任务无关统一骨干在参数量和计算量两个维度上都具有更高的 GAUC 转化效率，且规模越大优势越明显。
- 在线 A/B 结果表明：
  - 使用时长 +3.0%；
  - 点击 +2.8%；
  - 点赞 +2.0%；
  - 评论 +3.6%；
  - 打招呼 +2.5%；
  - 深度聊天 +2.0%。
- 部署采用请求级共享计算后，P99 评分延迟降低约 30%，满足高并发在线推理需求。
- 核心结论：多任务建模不应只发生在预测头部，而应作为骨干内部的连续信息流，与序列和特征共同演化。
