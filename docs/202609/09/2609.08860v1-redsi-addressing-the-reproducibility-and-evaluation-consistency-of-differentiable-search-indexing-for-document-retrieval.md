## 摘要
可微搜索索引（DSI）框架（Tay等，2022）已成为生成式检索的事实基线。然而，DSI难以复现：没有公开实现涵盖全部三种原始文档标识符类型（原子型、朴素型、语义型），报告结果差异很大，且无处不在的NQ320K数据集是通过多样且欠规范的预处理从Natural Questions构建的。我们推出ReDSI，这是首个支持全部三种标识符类型的开源DSI实现，并附带一个可参数化且文档完备的NQ320K构建流程。实验上，我们取得了与先前DSI基线相当或更强的结果。此外，我们在模型缩减下进行了广泛实验，涵盖检索有效性、参数效率、训练方法和解码策略，为未来研究开辟了新方向。

## Abstract
The differentiable search index (DSI) framework (Tay et al., 2022) has become the de facto baseline for generative retrieval. However, DSI is hard to reproduce: no public implementation covers all three original document identifier types (atomic, naive, semantic), reported results vary widely, and the ubiquitous NQ320K dataset is built from Natural Questions through diverse and underspecified preprocessing. We introduce ReDSI, the first open-source DSI implementation supporting all three identifier types, together with a parameterizable and well-documented NQ320K construction pipeline.   Experimentally, we achieve results that are competitive with or stronger than previous DSI baselines. Moreover, we conduct extensive experiments under model downscaling, covering retrieval effectiveness, parameter efficiency, training methods and decoding strategies, opening novel directions for future research.

## 二、论文提出的方法论（核心思想、技术细节、公式与算法）

### 2.1 DSI 的形式化框架

设自回归模型为 pθ（encoder-decoder），词表为 V，文档集合为 D。

给定两个映射关系：

- 文本内容映射 vtext: D → V*；
- 文档标识映射 vdocid: D → V*。

检索目标：对查询 q，模型条件概率 pθ(vdocid(d)|q) 排序得到 Top-k：

bdθ(q) = argsort_k d∈D pθ(vdocid(d) | q)

训练目标为索引（indexing）与检索（retrieval）联合极大似然：

bθ = arg max θ  E[ log pθ(vdocid(d) | vtext(d)) ]  (索引项)  
+ E[ log pθ(vdocid(d) | q) ]  (检索项)

### 2.2 ReDSI 的三类标识符实现

- **原子（Atomic）标识符**：为每个文档在解码器词表外新增一个专用 token（如 <doc_0000>）|识别符长度=1，检索退化为“首解码步 Top-k 最大概率”，解码仅需一步。
- **朴素（Naive）标识符**：从预算范围 b≥|D| 中随机选取数字字符串（如 141913），用 T5 原生 tokenizer 切分（如 “141913”→ “14”+“19”+“13”+EOS）；识别符长度不定，检索需要 beam search 近似。
- **语义（Semantic）标识符**：利用无监督聚类（递归 KMeans，每层10簇，叶子簇≤100文档）构建十进制树路径，形成结构化前缀加局部序号（如 18510）；用 T5 tokenizer 再分词并解码。

### 2.3 数据集重建流水线

将 NQ→NQ320K 的构建解耦为两个维度：

1. **文档去重（Deduplication）**：根据某一比较运算符 doc=判断同一 Wikipedia 页面是否成为同一文档。
   - doc=text4k：比较序列化内容前 4000 个 Unicode 码点（作者尝试多种解释无法复现原始 228K 规模，仅获 202.2K）。
   - doc=title：NCI 风格，用 BERT-tokenize 并 decode 后的标题归一化键（109.7K）。
   - doc=url：用修订级 URL（231.7K）。
   - doc=pageid（作者新提案）：以 Wikipedia 持久 PageID 为身份依据，恢复率 99.95%（109.2K），与真实页面身份对齐最佳。

2. **文档序列化（Serialization）**：
   - **NCI NORM**：复用 NCI 管道——取标题 + 第一段，继承 NQ 预处理副产品（错距空白、字符替换），导致 <unk> 率极高。
   - **HTML NORM**（作者新提案）：从原始 byte 对齐 HTML 恢复表面文本——正确还原引号、破折号、空格；规范化列表/表格/自定义清理（去除 infobox、导航、参见/参考文献等尾部区块；剥离 IPA 发音注音）。前 32 token 内 <unk> 比例由 18.7% 降至 1.6%。

3. **索引–检索采样比例**：论文强调索引项与检索项期望的样本配比（a:b）是关键却被普遍省略的超参数。原始 DSI 采用 32:1；作者系统扫描后选择“自然比例”≈1:2.8（遍历一次数据 1 次文档索引 / 2.8 次查询检索）。

### 2.4 训练与评估设置

- 优化器：Adafactor，常数学习率，100 万步更新，batch=128；
- 解码：原子型直接用首步分布；多 token 用 beam size 40，再事后过滤（post-filtering），或使用 trie 约束解码；检查点按 dev-MRR@10 选择。

## 六、论文的主要结论与发现

1. **原子型标识符全面占优**：在所有模型尺度、所有数据集重建配置下，原子型 Hits@1/Hits@10/MRR@10 都领先朴素与语义型；且随骨干缩小性能衰减显著更小（Base→Efficient-Tiny：MRR@10 降 6.6 vs 朴素 13.6 vs 语义 12.2）。
2. **最优效果–参数权衡**：仅 44M 参数的原子型（Efficient-Tiny）MRR@10 62.2，超过 220M 参数的 T5-Base+朴素（60.1）与 T5-Base+语义（59.7）。
3. **训练速度优势明显**：T5-Base 下原子型 6.8 小时达到峰值 MRR@10（约65K步），朴素/语义需 >74.5 小时（约900K步）仍在缓慢提升。
4. **无效生成与标识符类型有关**：语义型 invalid 率始终低于朴素型，尤其在小模型尺度大幅下降（T5-Tiny：8.7% vs 37.5%），提示小模型语义结构可能更重要。
5. **解码方式不敏感**：trie 约束解码相比简单事后过滤无一致收益（差异通常≤0.6 点），即小模型不需要复杂解码也可保持效果；但更大的标识符空间预算会抬高 invalid 率，使过滤更有效。
6. **数据构建选择影响显著**：
   - doc=pageid 去重优于 doc=title（MRR@10 平均 +1.05 点），避免 550 条标题碎片化页面与 93 个跨页标题冲突。
   - HTML NORM 相对 NCI NORM 提升较小（+0.38 点）但显著降低 <unk>（18.7%→1.6%），对依赖文本内容的工作有更大意义。
7. **索引–检索比例是关键超参**：从 32:1 改为自然比 1:2.8 可带来巨大收益（原子型 MRR@10 60.51→69.42）；该参数被现有文献普遍忽略。
8. 自身结果与 Pradeep et al. (2023) 等强复现相当或更强，为后续研究建立了稳定的可复现锚点。

## 八、不足与局限

1. **评估覆盖面有限**：

   - 仅 T5 家族、最高 T5-Base（220M）与约 110K 文档规模；
