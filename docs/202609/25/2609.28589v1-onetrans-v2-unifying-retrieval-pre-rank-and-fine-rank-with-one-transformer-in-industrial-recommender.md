## 摘要
工业推荐系统通常以召回、粗排、精排的\emph{级联}方式运行，但这些阶段通常被训练和部署为相互独立的模型，导致用户序列被重复编码、优化过程彼此孤立，并带来重复的工程投入。在 OneTrans 的模型级统一基础上，我们提出 OneTrans-V2，用一个 Transformer 统一整个级联流程。它将用户行为序列一次性编码为共享上下文，同时保留各阶段特有的候选特征与计算。联合训练让三个阶段相互增强，并支持从精排到粗排的模型内知识蒸馏。我们以稀疏专家混合（MoE）扩展共享骨干网络，从而在有界激活计算下提升容量，并用 $μ$P 风格参数化稳定扩展过程。为整合面向不同目标的召回通道，我们提出决策条件生成式召回（DCGR）。DCGR 预测一个描述即将发生的交互的决策前缀，并以其为条件生成物品，使业务目标能够引导单一的生成过程。最后，序列原生训练（SNT）围绕每个用户的终身行为序列组织训练，并将其编码在多次曝光间摊销。OneTrans-V2 部署于一个大规模工业推荐系统的全部三个阶段，使商品交易总额（GMV）提升 9.74\%，并且在与协同设计的服务栈配合下，在相同硬件预算下达到其所替代级联系统的 $3.2\times$ 吞吐量。

## Abstract
Industrial recommendation systems typically operate as a \emph{cascade} of retrieval, pre-rank, and fine-rank, but these stages are usually trained and served as separate models, causing repeated user-sequence encoding, isolated optimization, and duplicated engineering effort. Building on OneTrans' model-level unification, we present OneTrans-V2, one Transformer that unifies the entire cascade. It encodes the user behavior sequence once as a shared context while preserving stage-specific candidate features and computation. Joint training lets the three stages reinforce one another and enables in-model knowledge distillation from fine-rank to pre-rank. We scale the shared backbone with sparse mixture-of-experts (MoE), which increases capacity with bounded activated computation, and stabilize scaling with $μ$P-style parameterization. To consolidate objective-specific retrieval channels, we introduce Decision-Conditioned Generative Retrieval (DCGR). DCGR predicts a decision prefix describing the upcoming interaction and generates items conditioned on it, allowing business objectives to steer a single generative process. Finally, Sequence-Native Training (SNT) organizes training around each user's lifelong behavior sequence and amortizes its encoding across exposures. Deployed across all three stages of a large-scale industrial recommendation system, OneTrans-V2 improves gross merchandise value (GMV) by 9.74\% and, with a co-designed serving stack, delivers $3.2\times$ the throughput of the cascade it replaces under the same hardware budget.

- **四条代价**：
  1. 工程重复：新特征、更长行为序列、扩容改进都要逐阶段实现、调参、验证、上线；
  2. 计算浪费：同一用户行为序列被每个阶段重复编码；
  3. 优化孤立：阶段间无法共享表示与监督，导致跨阶段排序不一致（粗排丢弃的候选精排再也无法找回）；
  4. 容量碎片化：模型容量分散在多个专用模型，无法整体扩展。
- **两条统一路线**：
  - 路线 A（以 OneRec 为代表）：用端到端生成模型**取代**级联，以排序器作奖励模型；但工业排序阶段高度依赖丰富的候选特征，去掉会显著降低质量。
  - 路线 B（本文）：**保留级联与候选集缩减**，把三阶段做成**同一个 Transformer 的三个任务**，共享与候选无关的用户上下文（图 1(b)）。
- **定位**：在 OneTrans（单排序阶段的模型级统一）基础上，把统一从「单阶段」推进到「整条级联」，即 **cascade-level One Transformer**。

## 2. 方法论

### 2.1 核心思想：按「可复用 vs 阶段特有」切分，而非按阶段切分
- 用户行为序列 $S=(s_1,\dots,s_L)$ 一次性编码为**共享因果用户上下文**（causal attention，防未来信息泄漏），三个阶段复用其 KV 状态。
- 各阶段仅追加自己的非序列（non-sequential）token：召回 $NS_r$、粗排 $NS_p$、精排 $NS_f$，由各自 tokenizer 生成。
- **混合参数化（mixed parameterization）**：行为 token 共享 Q/K/V 与 FFN 参数；阶段特有 token 使用 token 专属（非共享）参数，从而在同一个 Transformer 内保留异质特征表示。
- **阶段可见性掩码（Stage Visibility Mask）**：阶段 token 以其请求时间戳所对应的「最后一条已到达行为」为锚点，只可见该行为前缀、自身及同阶段同曝光的前序 token；跨阶段/跨曝光互相屏蔽；行为 token 永不 attend 阶段 token。因此用户上下文可被编码一次、被所有阶段只读复用。
- **阶段异构预算**：粗排用轻量特征子集 $NS_p \subset NS_f$ 压缩为**单个候选 token**（延迟最紧）；精排保留完整特征为**多个 token**（追求排序保真度）。

### 2.2 三任务联合优化
- 总损失（式 9）：$\mathcal{L}=\lambda_r\mathcal{L}_r+\lambda_p\mathcal{L}_p+\lambda_f\mathcal{L}_f+\lambda_{kd}\mathcal{L}_{kd}$，实验中取 $\lambda_r=0.1,\lambda_p=\lambda_f=\lambda_{kd}=1$，蒸馏温度 $\tau=0.5$。
- 召回为**自回归生成**，粗排/精排为**判别式打分**（CTR、CVR 的 BCE，式 6、7）。

### 2.3 DCGR（决策条件生成式召回）——整合多目标召回通道
- **物品标识**：三级语义 ID（SID₀–SID₂），由多模态 embedding 经 RQ-KMeans 量化得到（每级码本 8192），由粗到细自回归生成；召回是 SID 码树上的 beam search，命中同一 SID 的多个物品全部返回。
- **决策前缀**（插入在 SID 之前，类似「非语言的思维链」）：
  - 并行决策 $DT_p$：购买等级 $z_{oc}$、发现等级 $z_{disc}$、供给类型 $z_{ad}$（三者由 CTX 位置各自轻量头预测后**求和**，而非串行链式）；
  - 依赖决策 $DT_d$：消费等级 $z_{aov}$（仅在已知 $z_{oc}$ 后才有意义，故串行）。
  - 标签直接从行为日志读取（单步，无需奖励模型，也无需对旧策略样本重加权）。
- **联合分布**（式 2、3）：$P(z,\text{Item}\mid H)=P(z\mid H)\cdot P(\text{Item}\mid H,z)$，$H=(S,\text{CTX})$，按式 1 的顺序以交叉熵 + teacher forcing 训练。
- **业务引导（Business Steering）**：解码时先枚举所有合法决策组合并**单次前向打分**，再加业务偏移 $\beta\phi(z)$，随后 beam search 联合排序（式 4）：
  - 等价于 KL 正则化的改进步 $\max_q \mathbb{E}_q[\phi(z)]-\frac{1}{\beta}\mathrm{KL}(q\|P(\cdot|H))$；
  - 偏移只作用于决策部分，不改动物品项 $P(\text{Item}\mid H,z)$；$\beta=0$ 即模型自身排序；**$\beta$ 在线可调**，新目标只需加一个轻量决策头而非新建召回通道。
- **物品侧引导（未部署）**：以 classifier-free guidance（式 5）用 null token ∅ 训练，推理时用权重 $w$ 放大决策对 SID 打分的影响，形成「$\beta$ 决定选哪个决策、$w$ 决定物品多听决策」的双在线参数。

### 2.4 扩展与稳定性（TransBlock 设计）
- 每个 TransBlock：pre-norm + RMSNorm；残差乘子 $\gamma=1/\sqrt{2N}$；QKNorm 稳定注意力 logits；**门控注意力**（head 级 sigmoid 门控，抑制 attention sink 与 massive activation）；FFN 为**稀疏 MoE**。
- **MoE**：仿 DeepSeekMoE 的细粒度 SwiGLU 专家 + 1 个常驻共享专家；**sigmoid 路由器**（替代 softmax，避免专家耦合与赢者通吃，便于扩专家数）。
- **GQA**：分组查询注意力缩小共享行为序列的 KV cache（该 cache 需被三任务、以及召回的多个 beam 广播读取），质量无损。
- **$\mu$P / Depth-$\mu$P**（表 1）：隐藏层初始化 $1/d$、Adam 学习率按 $1/m_d$；残差乘子 $1/\sqrt{2N}$、深度学习率按 $1/\sqrt{m_N}$，使训练动力学对宽/深尺度不变，实现**超参零样本迁移**；配合 AdamW 的解耦权重衰减。
- **多模态 embedding**：不同于 SimTier 预先算相似度直方图，OneTrans-V2 直接把多模态 embedding 作为行为物品与候选的侧信息输入——该设计**只在容量充足时有利**。

### 2.5 SNT（序列原生训练）
- 以用户窗口为单位，行为序列**只存一份、只编码一次**，窗口内所有曝光（跨请求、跨阶段）共享该编码；每个曝光按锚点 $a_e$ 读取自己的**因果视图**（与线上所见完全一致）。
- 序列 append-only + 因果编码保证了新行为追加后旧前缀编码仍然有效（式 10）。
- **请求相对时间编码**：用基于时间戳的 RoPE，注意力项只依赖 $t_i-t_e$（式 11），同一曝光内 token 相对旋转抵消；key 的旋转只依赖行为自身时间戳，可**计算一次被所有请求与阶段复用**。
- 收益：训练加速 4.4×；序列特征存储降低 95%，非序列特征存储降低约一半。

### 2.6 服务与系统优化
- **共享用户上下文缓存 $C_u$**：一次编码，三阶段复用；服务仍走「召回 → 粗排 → 精排
