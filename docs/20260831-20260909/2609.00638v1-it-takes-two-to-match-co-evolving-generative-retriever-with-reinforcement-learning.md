## 摘要
检索是现代搜索和广告系统的首要阶段，它从庞大的物品空间中选出一个候选集，供下游的排序与拍卖使用。近期研究越来越多地借助大语言模型（LLM），通过查询扩展、数据合成和检索反馈训练来改进检索。然而，生成组件通常仅用于查询侧增强，最终匹配仍交由下游检索器完成。我们引入 CoGR——一种检索框架，它转而训练 LLM 在查询侧和物品侧直接构建检索表示。每个生成器都会产出一组精简的关键词，并通过倒排索引直接进行匹配，从而与现有的基于关键词的检索基础设施保持兼容。CoGR 采用两阶段训练流程：监督微调首先建立对齐的关键词空间，随后协同进化强化学习使用 GRPO 在对方侧冻结索引的约束下交替优化查询侧和物品侧生成器。两侧优化的是同样的查询-物品检索 F1 目标：查询侧直接获取检索 F1，而物品侧则获得一个反事实边际奖励，用于度量其生成的关键词所引起的查询侧 F1 变化。在 10 种具有代表性的稀疏、稠密和生成式基线中，CoGR 在内部 APP 市场数据集和公开的 WANDS 基准上均达到最佳性能，相对最强基线的 F1 分别提高了 10.9% 和 36.1%。进一步的分析表明，训练过程中协同进化稳定，查询-物品关键词空间愈发对齐。

## Abstract
Retrieval is the first stage of modern search and advertising systems, selecting a candidate set from a large item universe for downstream ranking and auction. Recent work increasingly leverages LLMs to improve retrieval through query expansion, data synthesis, and retrieval-feedback training. However, the generative component is typically used for query-side augmentation, while final matching is still delegated to a downstream retriever. We introduce CoGR, a retrieval framework that instead trains LLMs to directly construct retrieval representations on both query and item sides. Each generator produces a compact set of keywords, which are matched directly through an inverted index, preserving compatibility with existing keyword-based retrieval infrastructure. CoGR uses a two-stage training pipeline. Supervised fine-tuning first establishes an aligned keyword space, after which co-evolving reinforcement learning alternately optimizes the query- and item-side generators with GRPO against the opposite side's frozen index. Both sides optimize the same query-to-item retrieval $F_1$ objective: the query side receives retrieval $F_1$ directly, while the item side receives a counterfactual marginal reward measuring the change in query-side $F_1$ caused by its generated keywords. Across 10 representative sparse, dense, and generative baselines, CoGR achieves the best performance on both an internal APP Marketplace dataset and the public WANDS benchmark, improving $F_1$ over the strongest baseline by $10.9\%$ and $36.1\%$, respectively. Further analysis shows stable co-evolution and increasingly aligned query--item keyword spaces over training.

## 1. 核心问题与整体含义

- **研究背景**：检索是现代搜索与广告系统的第一级流水线，需从大规模物品空间中快速筛出候选集。经典方法可归为三类：稀疏检索（如 BM25）、稠密检索（双塔向量匹配）与生成式检索（直接用序列模型输出文档标识符）。近年来，LLM 被引入检索领域，通过查询扩展、伪文档生成或检索反馈训练改进效果。
- **痛点**：
  - 现有 LLM 增强检索通常只优化查询侧（如重写查询、扩展关键词），最终匹配仍依赖下游独立检索器，查询侧的改进与物品侧表示并不对齐。
  - 生成式检索虽有潜力，但严重依赖标识符设计，面临解码可扩展性和泛化问题，难以直接替换工业级倒排索引基础设施。
  - 缺少一个能让查询端和物品端表示在**同一检索目标的反馈下共同演化**的框架。
- **核心问题**：能否让 LLM 直接在查询侧与物品侧同时构建检索表示，并用统一的检索指标来协同优化两端生成器？
- **整体含义**：论文提出 CoGR（Co-evolving Generative Retriever），让查询侧与物品侧的 LLM 各生成一组关键词，直接通过倒排索引匹配，从而在不改动现有关键词检索基础设施的前提下，实现双端生成器的协同进化。该框架在内部 APP 市场和公开 WANDS 基准上相对最强基线将 F1 分别提升了 10.9% 与 36.1%。

## 2. 方法论

- **总体架构**：训练两个独立的 LLM 生成器——查询侧生成器 \(G_q\) 和物品侧生成器 \(G_i\)。给定查询 \(q\) 或物品 \(i\)，分别输出紧凑关键词集 \(S_q = G_q(q)\)、\(S_i = G_i(i)\)。检索时通过倒排索引匹配关键词重叠的物品，并用 BM25 对召回的物品排序。
- **两阶段训练流程**：
  1. **阶段一：监督微调（SFT）初始化**
    - 先用基础 LLM 为每个物品生成 \(M\) 个关键词，得到初始物品关键词集 \(S_i\)。
    - 对每条查询 \(q\)，汇集其相关物品的初始关键词，按词频选出 top-\(N\) 个词作为查询侧目标 \(S_q\)。
    - 分别对查询侧（以 \((q, S_q)\) 为样本）和物品侧（以 \((i, S_i)\) 为样本）做 SFT。
    - 作用：打破“鸡生蛋”困境，先建立一个初步对齐的关键词种子空间，确保 RL 阶段有足够的初始召回以提供有意义的奖励信号。
  2. **阶段二：协同进化强化学习（Co-Evolving RL）**
    - 交替训练查询侧与物品侧生成器，每次更新时对方侧的索引保持冻结，使当前侧面对的是一个固定检索环境。
    - **查询侧奖励**：采样多个关键词集，利用冻结的物品索引执行检索，以检索 \(F_1\) 作为奖励；超过关键词预算 \(K_{\max}=30\) 则奖励为 0。用 GRPO 对组内奖励做归一化后更新。
    - **物品侧奖励（反事实边际奖励）**：给定候选关键词集 \(S_i\)，将物品 \(i\) 在索引中的关键词替换为 \(S_i\)，其余物品保持不变，计算检索整体 F1 变化量：\(R_i(S_i)=R_{\text{new}} - R_{\text{old}}\)。超过预算则奖励 \(-1\)。实现上通过缓存每个查询的检索计数（召回数、命中数、相关数）以及受影响的查询集合，将奖励计算开销降为只对受影响查询做常数时间更新，无需重新构建索引或跑全量检索。
    - 版本迭代：如 Algorithm 2 所示，循环 5 轮，每轮先训练查询侧、重建查询索引，再训练物品侧、重建物品索引，如此交替推进。

- **个性化扩展**：奖励可用加权 F-measure 替换标准 F1；RL 算法也可换用 PPO 等，框架具灵活性。

## 3. 实验设计

- **数据集**：
  - **内部 APP 市场数据（Internal）**：13,500 训练查询 / 1,500 评估查询，物品为约 39,600 个 APP，平均每个查询约 1,000 个相关物品。
  - **WANDS（公开，Wayfair 产品搜索）**：430 训练查询 / 50 评估查询，约 42,994 个产品，平均每个查询约 200 个相关物品。
  - 两者均提供查询-物品相关性类别标签（Internal 为五级 LLM-judge 标签，WANDS 为三级人工标签，均二值化处理）；仅按查询维度划分训练/验证，物品全集在训练与验证间共享。
- **Benchmark 与基线**：共 10 个代表方法，涵盖三个检索家族：
  - 稀疏检索：BM25、SPLADE-v2；
  - 稠密检索：DPR、ANCE、Qwen3-Embedding-4B（零样本）、ANCE-Qwen4B（微调版）；
  - 生成式检索：DSI、DSI-QG、RIPOR、DeepRetrieval（其训练的是查询重写 LLM，与 CoGR 查询侧 RL 最接近）。
  - CoGR 自身使用 Qwen3-4B-Instruct（CoGR-4B）和 Qwen3-1.7B（CoGR-1.7B）两种规模。
- **评估指标**：宏平均 Precision/Recall/F1（对基线在训练集上搜索最优截断点后应用到验证集），以及 MRR@100、NDCG@100、P@100/R@100/F1@100；附录 C 另给出 cutoff=10 和 1000 的结果。
- **消融实验**（Internal 数据）：无物品描述（-Description）、查询侧增加搜索线索（+Search Results）、物品侧奖励替换为对称的物品视角 F1（Transposed F1）、左右侧共享同一生成器（Shared generator）、去掉 SFT 预热（No SFT）。

## 6. 主要结论与发现

- CoGR 在内部 APP 市场与 WANDS 两个数据集上均取得最佳 F1（分别为 0.3963 与 0.6819），相对各自最强基线（ANCE-Qwen4B）提升 10.9% 与 36.1%。
- **双端共演化比单端 RL 更有效**：只优化查询侧（CoGR、DeepRetrieval）显著逊于完整 CoGR，说明只改进查询侧表示而不调整物品侧表示是不够的。
- **交替训练的共演化是稳定的**：验证 F1 从 SFT 后的约 0.16 稳步提升至 5 轮训练后的约 0.40，单轮内先升后稳，未出现震荡发散。
- **关键词空间持续对齐**：训练后关键词从高频宽泛 unigram 转向更具体、信息量更大的多词短语；unigram 占比从 37% 降至 13%，3+ 词短语占比从 12% 升到 31%；查询侧与物品侧词表规模在 3–4 轮训练后趋于收敛。
- **额外信息增益**：增加查询端搜索线索可将 F1 提至 0.4379；物品描述为标题信息不足的物品提供了重要词汇线索（去掉描述 F1 降至 0.3759）。
- **工程可行性**：生成的直接是关键词，可无缝接入现有倒排索引与 BM25 排序；物品侧反事实奖励的增量计算方案在不重跑全量检索的前提下高效求得。

## 7. 优点

- **问题建模视角新**：从“查询-物品双端关键词空间对齐 + 统一检索目标协同演化”的角度切入，而非单纯优化查询改写，更贴近工业搜索中索引与查询须同步演进的现实。
- **保持工业兼容性**：生成结果为关键词，直接落到倒排索引上，无需引入向量库或专用稠密索引，解决了生成式检索难以落地的关键痛点之一。
- **奖励设计的对称性与可解释性**：查询端直接由检索 F1 驱动，物品端由反事实边际贡献驱动，二者优化的是同一个小写目标，逻辑上清晰一致。附录还给出了高效的增量奖励近似方案，这在工程上很实用。
- **RL 过程设计谨慎**：先 SFT 保证初始对齐、再交替更新并冻结对面索引，避免了两侧同时演化导致的非平稳环境问题，训练稳定性好。
- **消融充分、分析细致**：不仅有整体性能消融（Transposed F1 / Shared generator / No SFT），还有关键词词表演化的细粒度分析（词长度分布、双边词表收敛），能够解释“为什么会涨”。
- **实验覆盖面较广**：在同一框架下对不同规模（1.7B 与 4B）、不同输入信息条件、不同截断深度都做了报告。

## 8. 不足与局限

- **训练成本较高**：需训练两个 4B 级 LLM，且“训练→重建索引→交替”在 5 轮循环中反复执行，总体算力消耗大。论文仅说明 8×B200，未提供总 GPU 时数或成本估算，不利于落地层面的预算评估。
- **RL 奖励仅限于相关性 \(F_1\)**：未纳入商业目标（如收入、广告副作用、点击率等）的优化，而论文在引言中明确承认这一步对搜索和广告业务的决定性影响。
- **排名层简单**：匹配后的排序仅用 BM25 对关键词做词袋打分，并不精细，有进一步提升空间。
- **WANDS 验证集只有 50 条查询**，且类别约 200 条相关/查询，评估结果方差不小；论文未做多次运行/显著性检验，无法判断部分差距是否在噪声范围内。
- **数据集域单一**：仅覆盖 APP 市场和产品搜索，物品均为短文本（标题+描述），对长文档、新闻、代码、多模态内容等场景未做验证。
- **消融基线选择有限**：No SFT 的对比从基础 checkpoint 随机启动 RL，但未与“仅 SFT 不 RL”“仅 RL 无 SFT 但仍做一定数量的随机探索”等中间态做网格对比；Shared generator 的初始化和参考策略细节也需更多说明。
- **未讨论生成关键词的零命中率/冷启动问题**：当 query 或 item 侧生成的关键词与对面完全无交集时，该模式如何退化和补救（例如是否回退到原始文本 BM25 兜底）没有涉及。
