## 摘要
工业推荐系统通常依赖于级联的召回、预排序、排序和重排序阶段，这些阶段分别优化的模型限制了扩展性、割裂了决策过程，并缺乏语义知识和推理能力。我们提出了TGR（腾讯生成式推荐），这是一个工业框架，沿三个耦合方向将推荐推向生成范式。TGR-GenRank通过CCFormer升级排序，CCFormer结合了统一特征标记化、可扩展的Transformer主干、特征字段分离的交叉注意力、子空间标记混合和分层序列压缩，同时保留逐项多任务输出。TGR-GenRec探索了两种范式下的端到端生成：BARGE通过项上下文感知注意力、层次路径重排序和正交双路径解码，弥补了层次语义ID生成中的项边界损失和语义漂移；HiGR则通过前缀结构语义ID、从粗到细的解码和列表级多目标对齐，执行整页生成。TGR-Reason将离线生成的语义ID推理标记注入在线解码，无需请求时展开即可提供推理能力。TGR已部署在腾讯多个生产场景，服务数亿用户。CCFormer在五个A/B测试场景中带来显著提升，并在其中两个场景全面上线，包括点击率提升3.57%和广告收入提升1.71%。BARGE在全面上线后，Hit@5提升10.2%-16.9%，点击率提升0.60%，阅读时长提升1.70%。HiGR将离线页面质量提升15.9%-21.3%，推理速度提升5倍，观看时长最高提升1.22%，视频观看次数最高提升1.73%。TGR-Reason将冷启动新用户的Hit@1提升477.8%，并实现有效消费提升1.75%、新用户曝光到转化的在线转化率提升13.09%。

## Abstract
Industrial recommender systems typically rely on cascaded retrieval, pre-ranking, ranking, and reranking stages, whose separately optimized models limit scaling, fragment decision making, and lack semantic knowledge and reasoning. We present TGR (Tencent Generative Recommendation), an industrial framework that advances recommendation toward the generative paradigm along three coupled directions. TGR-GenRank upgrades ranking through CCFormer, which combines unified feature tokenization, a scalable Transformer backbone, feature-field separated cross attention, subspace token mixing, and hierarchical sequence compression while retaining per-item multi-task outputs. TGR-GenRec explores end-to-end generation under two paradigms: BARGE bridges item-boundary loss and semantic drift in hierarchical semantic-ID generation through item context-aware attention, hierarchical path reranking, and orthogonal dual-path decoding; HiGR performs whole-slate generation with prefix-structured semantic IDs, coarse-to-fine decoding, and listwise multi-objective alignment. TGR-Reason injects offline-generated semantic-ID reason tokens into online decoding, providing reasoning without request-time rollout. TGR is deployed across Tencent production surfaces serving hundreds of millions of users. CCFormer delivers significant gains in five A/B-tested scenarios and is fully launched in two, including +3.57% CTR and +1.71% advertising revenue. BARGE improves Hit@5 by 10.2-16.9% and yields +0.60% CTR and +1.70% reading time after full rollout. HiGR improves offline slate quality by 15.9-21.3% with a 5x inference speedup and achieves up to +1.22% watch time and +1.73% video views. TGR-Reason raises cold-start new-user Hit@1 by 477.8% and delivers +1.75% effective consumption and +13.09% new-user exposure-to-conversion online.

## 1. 核心问题与研究动机

论文指出，工业推荐系统十余年来沿用的级联架构（召回→预排序→排序→重排序）正面临三大结构性挑战：

- **扩展瓶颈（架构不再把算力转换为质量）**：传统 DLRM 采用分立的特征抽取、特征交互与表示变换模块，受限于内存带宽，模型 FLOPs 利用率低，且缺乏类似 LLM 的可预测 scaling law——增大参数与算力不再带来质量提升。
- **决策割裂（逐阶段、逐点决策与列表级体验错位）**：级联式逐阶段优化与候选截断造成信息损失与目标漂移；pointwise 的逐物品打分无法刻画用户实际体验的"有序列表"中的物品间依赖与位置效应。
- **模式匹配而非推理**：基于行为共现与 ID 表示的传统模型缺乏多模态语义、世界知识与有意识推理能力，在冷启动、长尾和意图模糊场景下表现受限；而现有 LLM 推理路线（如链式思考、潜在状态 rollout）在请求路径上逐次执行的成本无法被工业延迟预算吸收。

**整体含义**：论文主张将推荐从"级联判别式架构"向"生成式范式"推进，并构建了 TGR（Tencent Generative Recommendation）工业框架——在腾讯 PCG 的新闻、视频、小说等异构业务中大规模部署，服务数亿用户。

## 2. 方法论

TGR 栈沿三条耦合方向推进，共享底层基础组件（统一语义 ID 分词器家族、用户/上下文编码接口、Numerous-Torch 训练与推理基础设施）：

### 2.1 TGR-GenRank（生成范式排序）—— CCFormer

在不推翻级联架构的前提下，将排序模型升级为 Transformer ranker。核心机制：

- **统一的特征 token 化**：用户画像、行为序列、目标物品被划分为三个语义字段的 token 流。
- **特征字段分离的交叉注意力**（Feature-Field Separated Cross Attention）：以三条有向注意力流替代全局自注意力——user→sequence（偏好检索）、target→sequence（目标-历史相关性）、target→user（目标-用户兼容性）；目标 token 之间互不 attend，从而支持单次前向对所有候选并行打分。
- **子空间 token mixing**：将序列张量重塑为覆盖 m 个相邻行为 token 与 n 个隐藏通道的子空间，用独立门控逐通道 FFN 实现线性复杂度的序列内交互。
- **相对时间-位置编码在 token 子空间内注入**：以 O(Lsm) 代价纳入行为新鲜度信息，避免 O(Ls²) 注意力矩阵偏置。
- **分层序列压缩**：每个 block 后通过步长卷积（kernel k, stride s）融合相邻行为 token，使深层 block 在几何级递减的代价下获得全历史感受野。

训练采用多任务监督（engagement/retention/monetization heads）、BF16/FP16 混合精度、INT8+双哈希稀疏参数压缩，在 Numerous-Torch 上实现单次前向并行候选打分（QPS 提升 30%）。

### 2.2 TGR-GenRec（端到端生成推荐）

按生成粒度分为两种互补范式，各有一个生产模型：

**BARGE（NTP 单物品生成范式）**——针对层次化语义 ID 生成的两个结构缺陷：

- (P1) **物品边界缺失**：RQ-VAE 分层 SID 被压平后，编码器丢失物品边界；同一 codeword 在不同前缀下语义不同。
- (P2) **语义漂移**：层次码本树上任何一层的解码错误都会将搜索导向错误的子树，使目标物品不可达；扩大 beam 无法根治。

三个轻量模块修复上述缺陷：
- **ICA（Item Context-Aware Attention）**：对每个物品的 L 个 SID token 用可学习 query 做交叉注意力聚合，通过门控残差注入物品级上下文（门值集中约 0.35–0.38，保留 token 级信号）。
- **HPR（Hierarchical Path Reranking）**：解码层 l 处用双塔 scorer 打分解码器 hidden state h0 与累计路径嵌入 p(l) 的兼容性，以对称 InfoNCE 联合训练（负例含 batch 内路径、高概率错误前缀、业务负反馈），推理时以权重 λ 与生成对数概率融合重排 Top-N 池。
- **DPD（Dual-Path Decoding）**：OSQ-VAE 通过可学习 Householder 正交旋转 R（R⊤R=I）将物品表示切分为两个正交子空间，各用独立残差码本生成双通道 SID；两个解码塔的 Top-K 列表经 LSE soft-OR 融合，实现跨通道互补召回。

**HiGR（NSP 整页生成范式）**——将整个有序列表作为单一生成单元，解决三个 disconnect：

- (D1) **PCRQ-VAE 分词器**：RQ-VAE 基础上加入全局量化项（防止深层码本残差消失）和前缀对比学习目标（约束前 D−1 层使语义/协同相近物品彼此拉近，叶子层保留物品同一性）。
- (D2) **HSD（Hierarchical Slate Decoder）**：粗粒度 slate planner 在紧凑的偏好嵌入空间逐位置自回归规划（单次 greedily），共享的细粒度 item generator 将每个偏好锚定为一小段局部 SID 序列（beam search 仅限 D-token 的局部解码），辅以列表内多样性正则。
- (D3) **ORPO 列表级多目标对齐**：从隐式反馈构造满足三种目标的 slate 级正负偏好对——排序保真度（乱序排列）、真实兴趣（负面反馈物品）、多样性（过度相似列表），以无参考模型的 Odds Ratio Preference Optimization 进行整体对齐。

### 2.3 TGR-Reason（推理增强生成推荐）

将 LLM 推理从请求路径上完全移除，改为训练时摊销：

- **复用共享 SID 空间**：以"Reason Tokens（语义 ID）"作为推理与记忆的公共接口（而非文本 CoT 或隐藏状态）。
- **Think 模型（LatentRec 训练）**：Qwen3-1.7B 骨干 + LoRA。三个组件实现摊销——Continuous Thought Module（K 步潜在推理 rollout，由 Soft Token Selection 投影回输入嵌入流形以避免表示失配）、STS（64 个可学习的 soft token 保持投影可解码、Norm/Direction 不出流形）、Per-step Reasoning Loss（对每个中间态 hk 用共享预测头在衰减温度下监督第一层 SID）。生产配置 K=0（训练完丢弃推理模块，普通 SID 解码即可获得推理收益）。
- **注入方式**：离线生成 top-Kr 完整 SID（Reason tokens），经 **DRI（Direct Reasoning Injection）** 按码本层级重组为 Personal-Memory 条件化的层次对齐 prompt 插入解码器（不改变 SID 解码长度/beam 空间）；同时可经 **GMR（Reasoning-Guided Group Memory Retrieval）** 以 reason token 为查询检索群体行为后续序列并做双记忆（Personal vs Group）编码与自适应门控融合。

- **BARGE**：2 个公开数据集 + 2 个工业场景；与 5 种以上最强基线对比；带 codebook 控制的变体（BARGE-base）隔离机制增益；组件消融（增益近似可加）；效率对比（参数量/训练/推断耗时）；线上 A/B + 长期 holdback + 检索通道级对比（4 个通道并列）。
- **HiGR**：1 个公开数据集 + 1 个工业数据集；10 个指标全面对比；三组件消融（PCRQ-VAE 各层对比约束的碰撞率分析、HSD 去除 ILD/context embedding、ORPO vs DPO 及三目标联合 vs 分离）；0.05B–2B 参数 scaling（6 档）；质量-效率与 KV-caching 组合对比；3 个线上场景。
- **TGR-Reason**：3 个用户队列（全体/主推荐流量/冷启动）× 5 个 Hit@K 截断点；暖/温/冷分桶验证离线解码与参考解码一致；线上 A/B 显著性验证。

**公平性评估**：论文声明每方法均接受独立 TPE 超参搜索、同硬件栈运行；OneRec 自实现用于离线对比；HiGR 在匹配参数规模（25M）下对比，并附 100M 放大对照；BARGE 的 efficiency 对比在相同配置下展开。整体实验设计在工业论文中属于相当充分且相对客观的。
