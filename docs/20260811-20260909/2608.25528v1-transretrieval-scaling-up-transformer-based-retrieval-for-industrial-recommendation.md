## 摘要
将缩放法则应用于推荐检索受到特征异构性的阻碍：简单地堆叠Transformer层会产生递减的收益，因为异构字段会导致严重的令牌范数发散。我们提出了TransRetrieval，一个基于Transformer的检索框架，随着计算预算和跨域数据同时扩展。关键使能因素是(1)加权平均聚合，恢复了Transformer所依赖的同质令牌假设。在此基础上，我们引入了(2)目标令牌压缩，将每个候选的FLOPs减少85%，同时保留交叉注意力的表达能力，以及(3)位置式域嵌入，以可忽略的额外成本统一多个域，将跨域数据转化为扩展资产。在400亿交互的工业数据集和公开的KuaiRand基准上，将每个目标的计算量从0.1扩展到2 MFLOPs，召回率@2000提高了+19.3/+22.2个百分点，证实了稳健的对数线性缩放。在在线A/B测试中，TransRetrieval在与生产基线相同的端到端延迟约束下，使平台收入提升了2.53%。

## Abstract
Applying scaling laws to recommendation retrieval is hindered by feature heterogeneity: naively stacking Transformer layers yields diminishing returns because heterogeneous fields produce severe token-norm divergence. We present TransRetrieval, a Transformer-based retrieval framework that scales with both computational budget and cross-domain data. The key enabler is (1) weighted average aggregation, which restores the homogeneous-token assumption Transformers rely on. Building on this, we introduce (2) target token compression that cuts per-candidate FLOPs by 85% while preserving cross-attention expressiveness, and (3) position-style domain embeddings that unify multiple domains at negligible additional cost, turning cross-domain data into a scaling asset. On a 40-billion-interaction industrial dataset and the public KuaiRand benchmark, scaling compute from 0.1 to 2 MFLOPs per target yields +19.3/+22.2 pt Recall@2000, confirming robust log-linear scaling. In online A/B tests, TransRetrieval lifts platform revenue by 2.53% under the same end-to-end latency constraint as the production baseline.

### 1. 核心问题与整体含义

推荐系统拥有海量数据和不断增长的计算预算，却一直未能呈现出类似大语言模型那样的可预测“缩放定律”（Scaling Law）——即模型性能随模型大小、数据量和计算量呈对数线性增长。已有研究如 Wukong 指出，传统深层推荐模型在简单扩大规模时收益递减甚至出现负收益。论文将这一矛盾的根源归结为**特征异构性（Feature Heterogeneity）**：

- 推荐系统中的特征在本质上比 NLP 中的 token 或 CV 中的 patch 更具异质性——用户画像、行为序列、物品属性等不同字段被映射为 Transformer 输入 token 时，会产生**严重的 token 范数发散（token-norm divergence）**，导致注意力权重被高范数 token 主导，结构性扭曲了嵌入空间，使简单堆叠 Transformer 层收敛到次优解。
- 此外，工业级召回系统对**延迟约束极为苛刻**：候选池最多可达 10⁸ 量级，延迟预算仅为几十毫秒；多个业务域并行维护独立模型会造成成本倍增，而少数据域又缺乏从缩放中获益的数据量。

针对上述三大瓶颈，论文提出 **TransRetrieval**，旨在将缩放定律真正引入推荐系统的**召回（Retrieval）阶段**，并同时实现随计算预算和跨域数据规模的同步扩展，弥补此前研究（如 Climber）仅在排序（Ranking）阶段验证缩放的空白。

### 2. 方法论：三维度协同设计

TransRetrieval 运行于 NANN 确立的“模型驱动检索”范式之下：一个 DNN 打分函数 `s(u,i)=F_θ(u,i)` 在 HNSW 图上驱动波束搜索，每次遍历只访问语料中很小比例 ρ 的候选（部署场景中语料 5200 万条目，实际打分约 4×10⁴ 个）。框架的核心创新由三个轻量级设计构成：

**（1）加权平均聚合（Weighted Average Aggregation）——处理特征异构性**

- 若采用传统的加权求和聚合，用户侧字段因具有多值特征，输出范数会随特征基数 n_f 增长——用户侧 token 范数可达到目标侧的 10 倍。加权平均聚合通过除法同时抵消了特征基数累积和异构权重量级，使输出范数仅由嵌入表自身分布决定：

  \[
  \tilde{e}_f = \frac{\sum_{i=1}^{n_f} v_i \cdot h(k_i)}{\sum_{i=1}^{n_f} v_i + \epsilon}
  \]

- 论文通过对比论证了为何不使用替代方案：Max Pooling 有 O(√ln n_f) 的极值偏差且丢弃大部分信息；聚合后接 LayerNorm 经验上表现不佳且会抹除非均质字段的感知信号；加权平均是一个封闭解析式线性组合，无需学习统计量，能无条件地将输出尺度和 n_f 解耦，恢复 Transformer 赖以工作的同质 token 假设。

**（2）目标 token 压缩（Target Token Compression）——控制延迟**

单个请求的所有候选共享同一位用户，因此用户侧 K/V 只需每请求计算一次并被所有候选复用。候选侧总 FLOPs 可表述为：

\[
\text{FLOPs}_{total} \approx 4D \cdot N_{target} \cdot L_t \cdot (4D + L_u) \cdot N_{layer}
\]

在所有因子中，目标 token 数 L_t 最有压缩空间。论文采用一个 3 层 MLP（隐藏维度 [8D, 4D, D]，PReLU 激活，层间 LayerNorm，末层纯线性投影）将目标侧全部聚合嵌入拼接映射为**单个 D 维 token**。该压缩不是妥协而是“战略再分配”——可将释放的 85% FLOPs 重新投入放大 D 和 N_layer，并天然提供固定维向量用于 HNSW 索引。

**（3）位置风格域嵌入（Position-style Domain Embedding）——跨域统一**

- 简单拼接表示域的 token 会带来 O((L+N_t)²) 的注意力膨胀。TransRetrieval 借鉴位置编码思想，使用一个可学习向量 s_d（按域索引），对所有 token 做逐元素加法：

  \[
  \tilde{e}_f = e_f + s_d
  \]

- 关键洞察在于：域信息仅通过相加进入模型，故所有 Transformer 参数（注意力头、FFN 层）在各域间无条件共享，每个域的每个训练样本都向同一套参数贡献梯度——稀疏域不再数据饥饿。这对比 MMoE/PLE 的“门控软路由会隐式分割梯度流”具有本质优势，使跨域数据成为真正的缩放资产。

**系统实现**还涵盖了与模型架构协同设计的推理系统优化：用户缓存广播（expand 算子替代逐候选复制，延迟降低 30%）、多候选打包批处理与算子融合（forward 延迟较朴素实现降低 11×）、全 GPU 检索管线（延迟降低 89%）、索引量化（服务并发量提高 3×）以及目标压缩器近线更新机制。

### 6. 主要结论与发现

1. **验证了召回阶段的对数线性缩放定律**：在工业数据集上 Recall@2000 从 0.464 提升至 0.657（+19.3 pt）；KuaiRand 上从 0.251 提升至 0.473（+22.2 pt），算力范围 0.1→2 MFLOPs′/目标。拟合曲线的 R² = 0.82/0.88，表明趋势高度一致且可预测。

2. **TransRetrieval-64D3L（0.45 MFLOPs′）已全面超越生产基线（0.576→0.603 Overall Recall@2000），且算力节省 35%；128D5L 配置更将性能推至 0.657**，并在相似算力下显著超越 HSTU（0.527）和 RankMixer（0.452）等可扩展基线。

3. **最值得注意的效率对比**：TransRetrieval-128D5L（1.91 MFLOPs′）比 RankMixer-768D16T（150.99 MFLOPs′）召回高 12.6 pt，同时算力少两个数量级。

4. **两个架构设计原则得到验证**：
   - “先压缩再放大”严格支配“更多 token + 更小骨干”：1-token + 128D5L（1.91 MFLOPs′，0.657）优于 8-token + 64D3L（3.04 MFLOPs′，0.624）。
   - 加权平均聚合是最优特征融合算子；位置风格域嵌入比 20 个重复域 token 性能更高（0.603 vs. 0.452）且算力保持恒定（41.3 MFLOPs 不变）。

5. **跨域数据共享是净正收益**：单域训练的各域总体 Recall 仅 0.579，而统一多域模型的单域数据单独训练结果和统一训练对比表明跨域迁移受益显著。

6. **部署价值**：整月线上 A/B 测试中，平台收入提升 2.53%（95% CI: 2.22%–2.70%，p<0.0001）、RPM 提升 1.28%，而端到端延迟与生产基线一致，用户体验稳定，广告主 ROI 保持可比。

### 7. 优点

1. **“参数免费”的关键创新**：缩放突破来自一个无需学习的单行修复（加权平均聚合），而非架构复杂化，可被社区快速迁移复用。

2. **三个设计高度协同、层层递进**：加权平均修复输入表征 → 目标压缩释放算力空间 → 域嵌入引入数据扩展资产。每一层都解决前一设计暴露出的瓶颈，逻辑链完整。

3. **“压缩即再分配”的认知框架**：将 token 压缩论证为比多 token 小骨干更优的帕累托前沿点，打破了“保留完整结构才保性能”的直觉。

4. **位置风格的域嵌入**以零注意力成本实现参数级完全共享，避免了门控架构中梯度流分割的问题，设计优雅。

5. **工程系统化**：缓存广播、批量算子融合、GPU 全检索、索引近线更新等系统优化已被 LLM 推理框架忽略的极端长宽比场景做了专门的工业级打磨。

6. **评估完整性优秀**：从离线双数据集到消融到在线 A/B，从 Recall、FLOPs 效率到商业指标、域级子分析，形成了多维度证据链。
