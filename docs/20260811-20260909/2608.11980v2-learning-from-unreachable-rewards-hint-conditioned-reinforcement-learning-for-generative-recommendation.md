## 摘要
语义ID生成式推荐器将每个物品表示为一段简短的离散语义令牌序列，并通过自回归生成该令牌序列来预测下一个物品。这种范式为物品ID、历史记录和物品文本提供了统一的生成接口，但也在基于奖励的后训练期间造成了结构化的优化瓶颈：当一个早期语义令牌进入物品令牌空间的错误分支时，有限的rollout组很少能到达真实物品，因此组相对优化会收到相同的零奖励，并且无法产生有用的优势。我们提出了提示条件生成式推荐（HCGRec），这是一种语义ID生成式推荐框架，能够为这类困难训练样本恢复学习信号。HCGRec通过使用检查点rollout对每个样本进行诊断，并且仅在当前生成器无法到达正确物品时，提供最小的目标前缀提示。然后，模型在提示的语义分支下生成未提示的后缀，将零奖励组转化为对物品令牌补全的信息性比较。提示也改变了令牌的身份：提示的前缀令牌是oracle提供的物品上下文，而未提示的后缀令牌是采样的生成动作。因此，我们引入了提示感知的信用分配，利用监督学习来保持提示令牌的物品语义和前缀结构对齐，并使用GRPO来优化采样的后缀。在序列推荐基准上的实验表明，HCGRec相对于监督微调和普通基于奖励的后训练有显著改进，同时将零优势训练样本从超过70%降低到20%以下。代码可在 https://github.com/WncFht/GRec 获取。

## Abstract
Semantic-ID generative recommenders represent each item as a short sequence of discrete semantic tokens and predict the next item by autoregressively generating this token sequence. This paradigm enables a unified generation interface for item IDs, histories, and item text, but it also creates a structured optimization bottleneck during reward-based post-training: when an early semantic token enters the wrong branch of the item-token space, finite rollout groups rarely reach the ground-truth item, so group-relative optimization receives identical zero rewards and produces no useful advantage. We propose Hint-Conditioned Generative Recommendation (HCGRec), a semantic-ID generative recommendation framework that recovers learning signal for such hard training instances. HCGRec diagnoses each instance with checkpoint rollouts and supplies a minimal target-prefix hint only when the current generator cannot reach the correct item. The model then generates the unhinted suffix under the hinted semantic branch, turning zero-reward groups into informative comparisons over item-token completions. Hinting also changes token identity: hinted prefix tokens are oracle-provided item context, while unhinted suffix tokens are sampled generation actions. We therefore introduce hint-aware credit decomposition, using supervised learning to preserve item-semantic and prefix-structure alignment for hinted tokens and GRPO to optimize the sampled suffix. Experiments on sequential recommendation benchmarks show that HCGRec substantially improves over supervised fine-tuning and vanilla reward-based post-training, while reducing zero-advantage training samples from over 70% to below 20%. The code is accessible at https://github.com/WncFht/GRec.

### 摘要

语义 ID 生成式推荐器将每个物品表示为一段简短的离散语义令牌序列，并通过自回归地生成该令牌序列来预测下一个物品。这一范式为物品 ID、交互历史和物品文本提供了统一的生成接口，但它也在基于奖励的后训练阶段造成了结构化的优化瓶颈：当一个早期语义令牌进入物品令牌空间中的错误分支时，有限的 rollout 组很少能到达真实物品，于是组相对优化只能收到相同的零奖励，无法产生任何有效优势。

为此，我们提出 **HCGRec**（Hint-Conditioned Generative Recommendation，提示条件生成式推荐）。该框架能够为这类困难训练样本恢复学习信号：HCGRec 先用检查点 rollout 对每个样本进行诊断，仅当当前生成器无法到达正确物品时，才补充一个最小的目标前缀提示。模型随后在该提示所引导的语义分支下生成未经提示的后缀，从而把零奖励组转化为关于物品令牌补全的信息性比较。

提示操作也改变了令牌本身的性质：被提示的前缀令牌是 oracle 提供的物品上下文，而未被提示的后缀令牌才是模型实际采样的生成动作。为此，我们提出**提示感知的信用分配**（hint-aware credit decomposition）：对被提示的令牌使用监督学习，以保持物品语义和前缀结构对齐；对采样的后缀则使用 GRPO 进行策略优化。

在多个序列推荐基准上的实验表明，HCGRec 相比监督微调和普通基于奖励的后训练均有显著提升，同时把“零优势训练样本”的比例从 70% 以上降至 20% 以下。代码已公开在 https://github.com/WncFht/GRec。

### 引言部分翻译（节选关键段落，含那条 arXiv 脚注句所在上下文）

生成式推荐将物品检索转化为类似语言模型的生成问题：模型不再对所有候选物品逐一打分，而是直接生成用户下一个可能消费物品的离散标识。对于大规模序列推荐，这一思路颇具吸引力，因为物品标识可以被组织为简短的语义 ID 令牌序列（通常通过对物品文本或多模态表示做聚类或残差量化得到），Transformer 随后即可通过自回归解码这些令牌来预测下一个物品。这也为与大型语言模型的结合提供了天然接口：交互历史、物品标题、描述等文本字段都可以用来将物品标识与模型的语义空间相对齐。

近来的语义 ID 生成式推荐器通常采用两阶段流程：先做监督式语义对齐，再做基于奖励的后训练。模型首先在若干语义对齐任务上进行监督训练，例如从历史语义 ID 序列、历史标题序列或物品侧文本中预测下一件物品的语义 ID；随后再使用推荐奖励进行优化，使生成物品与用户偏好和业务目标对齐。GRPO 是这一阶段常用的优化器，因为它比较同一提示下生成的多条物品令牌序列，且无需单独训练价值模型。

然而，其核心失败模式在于：在基于奖励的生成式训练中，许多语义 ID 训练样本在有限 rollout 下变得“不可达”。物品级奖励本身是稀疏的；更重要的是，这种稀疏性受到语义 ID 前缀树的组织方式影响。一条生成序列只有在到达真实物品或足够相关的物品时，才能得到有效信号；如果某个早期令牌选错了语义分支，后续令牌就始终在一个错误前缀下生成，几乎不可能再回到目标物品。因此，在当前生成器和固定 rollout 预算下，所有采样补全都可能停留在奖励可区分区域之外，所有奖励完全相同，GRPO 也无法产生任何相对优势。在我们记录的未加提示的后训练运行中，即使训练后期仍有大量 rollout 组处于不活跃状态，这意味着大量训练数据已不再提供有效的组相对更新。

本文认为，这里的障碍不仅是奖励稀疏，更是物品令牌空间中的**奖励可达性**问题。奖励塑形可以在生成序列被评估后提供更稠密的值；基于纠错的解码则可以在模型产出草稿后修复轨迹。这些策略都有价值，但并未直接回答训练阶段的问题：如果当前 rollout 分布几乎从不进入奖励可被区分的物品令牌树区域，语义 ID 生成器该如何从该样本中学习？

物品语义标识的结构提供了一个领域特异的答案：目标语义 ID 前缀本身就可以充当最小的脚手架，把一个不可达的训练样本拉回正确的物品分支。我们提出的 HCGRec 正是为困难的语义 ID 训练样本恢复可达性。在基于奖励的后训练之前，HCGRec 先用当前检查点对每个训练样本执行 rollout，以估计当前生成器下真实物品是否可达。如果模型已经能够生成目标物品，该样本就按原样训练；如果样本不可达，HCGRec 就暴露一个较短的目标前缀提示，例如第一个语义 ID 令牌，并让模型生成剩余后缀。该提示只在生成式推荐的训练阶段作为脚手架使用：推理时不增加任何额外信息，并且只应用于未加提示时无法产生学习信号的样本。

核心观察在于：提示本质上是**前缀树可达性控制**，而不是答案泄露。一个四令牌物品标识定义了物品空间中一条由粗到细的路径。当生成器反复选错第一个令牌时，后续后缀生成问题实际上是不适定的，因为所有后缀都基于错误分支进行条件生成。对这类困难样本揭示第一个令牌，等于把生成过程重新定位到正确的粗粒度分支；在此分支下，剩余令牌仍需由模型自己生成，组相对奖励也能区分出较优和较差的物品补全方式。这样就把原本不活跃的样本转化为有效的生成式训练组，同时保留了对未提示后缀的在策略学习。

HCGRec 还要求在带提示的语义 ID 生成中进行**提示感知的信用分配**。一旦目标语义 ID 的一部分被拼接到输入中，这些令牌就不再是推荐器采样的动作，而是 oracle 提供的物品上下文。如果把完整语义 ID 序列都视为生成动作，就会混淆两种不同来源的信息：被提示的前缀并非来自模型探索，不应获得 GRPO 信用；而未提示的后缀才是模型真实生成的部分，应通过 GRPO 优化。

同时，被提示的前缀也不能直接忽略，因为它承载了物品语义以及定位正确物品分支所需的由粗到细前缀结构。因此，我们用监督学习为被提示前缀提供语义锚定，用 GRPO 优化提示上下文下的采样后缀。这与全局式“监督 + 奖励”正则化不同：学习信号根据每个令牌究竟是 oracle 提供的物品上下文，还是模型生成的物品令牌动作来分配。

在实验上，HCGRec 通过把不活跃的困难样本转化为活跃生成训练组，有效改善了语义 ID 生成效果。我们在与基础生成式推荐器相同的语义索引设置下，于多个序列推荐基准上评估 HCGRec。主要结论是：具备可达性感知的提示方法可媲美并超越纯 SFT 训练和基于奖励的生成式基线，在多个关键推荐指标上都有提升，尤其在更深的 ranking 截断处（稳定的语义分支生成更为关键时）优势明显。更重要的是，它显著降低了后训练期间不产生梯度的零方差 rollout 组比例，从而改变了训练动态。消融实验进一步分离了提示策略、训练任务范围与提示感知信用分配的贡献，证明收益来自针对性可达性恢复，而非简单增加监督令牌。
