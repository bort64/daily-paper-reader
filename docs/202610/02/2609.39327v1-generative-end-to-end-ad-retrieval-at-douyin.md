## 摘要
生成式召回将推荐重新表述为离散物品 token 的生成。然而，将该范式扩展到真实世界的推荐系统时，暴露出两个关键瓶颈：1）表示坍缩，即物品标记器在持续分布偏移下收敛到退化结果，从根本上阻碍了稳定的端到端适配。2）物品碰撞，即海量候选池导致不同物品共享相同的 token 序列，损害最终召回精度。关键的是，这些瓶颈本质上是耦合的：扩大码本容量以缓解碰撞，会不可避免地加剧坍缩。为了同时解决这些问题，我们提出 GEAR，一个联合优化标记器、生成器和重排序器的端到端框架。为了缓解表示坍缩，我们引入 BasisVQ，它通过正交基对码本进行重参数化，以实现全局梯度共享和潜空间的刚性空间旋转，从而在没有特设启发式的情况下有效稳定梯度动态。我们进一步将其扩展为前缀感知的 BasisRQ，在相同的渐近时间复杂度下显著增强码本的表达能力。为了解决物品碰撞，GEAR 将上下文条件化的重排序头集成到生成过程中，以极小的计算开销高效地消歧发生碰撞的物品。通过在端到端生成式框架中统一稳定的标记化与联合重排序，GEAR 建立了一个完全可微且可扩展的范式。它目前服务于抖音广告的数亿日活跃用户，并在大量在线 A/B 测试中取得了显著的实证提升。

## Abstract
Generative retrieval reformulates recommendation as the generation of discrete item tokens. However, scaling this paradigm to real-world recommender systems reveals two critical bottlenecks: 1) Representation collapse, where the item tokenizer converges to degenerate results under continuous distribution shifts, fundamentally hindering stable end-to-end adaptation. 2) Item collisions, where the massive candidate pool causes distinct items to share identical token sequences, compromising the final retrieval precision. Crucially, these bottlenecks are inherently coupled: expanding codebook capacity to mitigate collisions inevitably exacerbates collapse. To address them simultaneously, we propose GEAR, an end-to-end framework that jointly optimizes the tokenizer, generator, and reranker. To mitigate representation collapse, we introduce BasisVQ, which re-parameterizes the codebook via an orthogonal basis to enable global gradient sharing and rigid spatial rotation of the latent space, effectively stabilizing gradient dynamics without ad-hoc heuristics. We further extend it to prefix-aware BasisRQ, substantially enhancing the codebook's expressiveness with the same asymptotic time complexity. To resolve item collisions, GEAR integrates a context-conditioned reranking head into the generative process, efficiently disambiguating colliding items with minimal computational overhead. By unifying stable tokenization and joint reranking within an end-to-end generative framework, GEAR establishes a fully differentiable and scalable paradigm. It currently serves hundreds of millions of daily active users on Douyin Ads, yielding substantial empirical improvements in extensive online A/B tests.

## 1. 核心问题与整体含义

- **研究背景**：生成式召回将推荐/广告召回重新表述为“离散物品 token 的自回归生成”，通常由 item tokenizer 将物品映射为 token 序列，再由 generator 自回归生成目标物品 token。
- **工业落地瓶颈**：
  - **表示坍缩（Representation Collapse）**：真实推荐系统持续经历分布偏移，直接反传更新 tokenizer 会导致梯度不稳定，码本大量“死码”，难以稳定端到端适配。已有做法如冻结 tokenizer、EMA、码本重初始化等，或牺牲动态适配，或只是启发式补丁。
  - **物品碰撞（Item Collisions）**：海量候选池中，不同物品可能因语义相似或码本容量有限而共享同一 token 序列，损害召回精度。追加唯一 token 会破坏语义泛化，后置重排又可能带来计算瓶颈或优化割裂。
  - **二者耦合**：扩大码本容量以缓解碰撞，会进一步加剧表示坍缩；孤立解决任一问题都不够。
- **整体含义**：论文提出 **GEAR**，一个端到端联合优化 tokenizer、generator、reranker 的生成式广告召回框架，旨在同时缓解表示坍缩与物品碰撞，并在抖音广告真实生产环境服务数亿日活用户。

## 2. 方法论

### 2.1 核心思想

- 通过训练-服务协同设计，将稳定 tokenization 与轻量联合重排统一在可微生成式框架中。
- 用 **BasisVQ / Prefix-aware BasisRQ** 解决表示坍缩并提升码本表达力；用 **上下文条件重排头** 解决物品碰撞；三者联合优化。

### 2.2 关键技术细节

- **BasisVQ：正交基重参数化码本**
  - 原始码本为 `C ∈ R^{N×d}`，引入可学习基矩阵 `W ∈ R^{d×d}`，重参数化为 `Ĉ = C Ŵ`。
  - 通过 Newton-Schulz 迭代近似正交化：`W ← 1/2 W(3I − W^T W)`，并归一化 `W ← W / max(||W||_F, ε)`，保证谱范数 `< √3`，满足收敛与数值稳定条件。
  - **几何直觉**：正交基使整个码本坐标系发生刚性旋转。活跃码驱动更新时，非活跃码也随之旋转，保持范数和相对拓扑，从而有机会重新接触新数据流形，复活死码。相比 Vanilla VQ 的稀疏更新和 SimVQ 的非正交冻结码本，BasisVQ 支持全码本动态更新。
  - **复杂度**：训练额外复杂度为固定 `O(d³)`，空间 `O(d²)`；推理时 `Ĉ` 可离线预计算缓存，复杂度与 Vanilla VQ 相同，零额外延迟。

- **Prefix-aware BasisRQ：前缀感知残差量化**
  - 将 BasisVQ 扩展到多层残差量化。
  - 每一层根据前面所有层的量化码，离散查表得到缩放 `γ` 和偏置 `β`，聚合成复合缩放与偏置，对当前层码本做逐元素仿射变换，使量化层具备前缀感知能力。
  - 为避免构造 `(b, N_l, d)` 大张量，定义 bias-shifted residual，并将 L2 距离矩阵分解为输入范数、缩放码本范数、交叉项三部分，用矩阵乘法实现，保持与 Vanilla VQ 相同的 `O(bN_l d)` 渐近时间复杂度。

- **Generator**
  - 编码器将非序列用户特征分组后经 FFN 投影，点击序列和转化序列分别经 FFN 投影，拼接为共享 KV 表示 `H`，供解码器 cross-attention 使用。
  - 解码器为 N 层 Transformer，包含 cross-attention、gated FFN、causal self-attention 和 RMSNorm，自回归输出各层词表概率。

- **Reranker**
  - 在生成 token 序列后，额外执行一步解码，输出经 MLP 转为用户表示 `u_rerank`。
  - 与 tokenizer 物品塔产生的物品嵌入 `v_i` 做点积打分：`s_i^rerank = u_rerank^T v_i`。
  - 该用户表示条件于用户和生成出的 token 序列，因此每个候选序列都有专属表示，可对碰撞物品做细粒度区分；仅增加一步解码和轻量点积，开销很小。

- **训练与推理**
  - 采用渐进 warm-up：先训练两塔 LLTR，再激活量化损失 `L_RQ`，最后激活生成损失 `L_Gen` 与重排损失 `L_Rerank`，避免 generator 依赖不稳定 tokenizer。
  - 损失包括：tokenizer LambdaLoss、RQ codebook/commitment loss、generator 加权交叉熵（曝光样本权重 `w = log(1 + secpm)`）、reranker LambdaLoss，最终加权求和。
  - 推理时使用 KV-cache beam search 解码候选 token 序列，检索对应物品，再用 reranker 打分，低精度 INT4 点积，并做每序列截断以促进多样性。

- **系统部署**
  - 包含流式训练、近线索引和在线服务。
  - Parameter Server 维护物品的 token 序列与嵌入；近线索引
