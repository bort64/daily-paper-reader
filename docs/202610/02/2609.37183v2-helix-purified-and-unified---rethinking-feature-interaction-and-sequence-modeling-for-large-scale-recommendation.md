## 摘要
工业推荐排序模型通常沿两条建模轴线扩展：对异构的用户、物品、上下文及交叉特征进行特征交互，以及对长时、信息丰富且多类型的用户行为历史进行序列建模。我们发现，单独扩展任一能力都不充分，因为二者均存在有限的扩展上限和次优的扩展律斜率。我们推测，若要获得更有利的扩展律斜率，需要联合扩展这两条轴线。为此，我们提出 HELIX，一种面向大规模推荐的纯化且统一的架构。HELIX 将序列检索与特征交互交织在一起，同时强制信息从可复用的序列状态单向流向以候选为条件的混合 token。该设计在保持两条建模轴线之间跨深度通信的同时，使用户侧序列计算可摊销，从而实现序列建模与特征交互的灵活且非对称扩展。HELIX 已部署于 TikTok 的电商推荐系统，持续提升离线 CTR AUC、CVR AUC 及其他排序指标。在线 A/B 测试中，其使用户人均电商视频 GMV 提升约 6%。

## Abstract
Industrial recommendation ranking models typically scale along two modeling axes: feature interaction over heterogeneous user, item, context, and cross features, and sequence modeling over long, informative, and multi-type user behavior histories. We find that scaling either capability in isolation is insufficient, as each exhibits a limited scaling ceiling and a suboptimal scaling-law slope. We conjecture that achieving a more favorable scaling-law slope requires jointly scaling both axes. To support this, we present HELIX, a purified and unified architecture for large-scale recommendation. HELIX interleaves sequence retrieval and feature interaction while enforcing one-way information flow from reusable sequence states to candidate-conditioned mix-tokens. This design preserves cross-depth communication between the two modeling axes while keeping user-side sequence computation amortizable, enabling flexible and asymmetric scaling of sequence modeling and feature interaction. Deployed in TikTok's e-commerce recommendation system, HELIX consistently improves offline CTR AUC, CVR AUC, and other ranking metrics. In online A/B tests, it achieves an approximately 6% increase in e-commerce video GMV per user.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：工业推荐排序模型沿两条建模轴扩展——
  - **特征交互（Feature Interaction）**：在异构的用户、物品、上下文、交叉特征上发现高阶组合，代表工作有 FM、DeepFM、DCN、Wukong、RankMixer、TokenMixer-Large。
  - **序列建模（Sequence Modeling）**：从长时、多类型的用户行为轨迹中识别意图与候选相关证据，代表工作有 DIN、DIEN、DSIN、HSTU、Ultra HSTU、STCA。
- **核心痛点**：
  - 单独扩展任一轴都不充分：两者都存在**有限的扩展上限**和**次优的 scaling-law 斜率**。
  - 作者推测：要获得更有利的缩放律斜率，必须**联合扩展两条轴**。
- **已有统一架构的三点不足**：
  1. **算子选择不当**：TokenMixer / UniMixer 表明自注意力未必是异构 token 的最优特征交互算子。
  2. **单步设计分散注意力**：OneTrans、SORT、MTFM 在同一步内同时做特征交互与序列检索，mix-token 的注意力被异构非序列输入稀释，削弱行为检索。
  3. **双向信息流破坏摊销**：InterFormer、Kunlun 允许候选侧特征更新用户侧序列状态，使序列状态依赖候选，无法通过 M-FALCON（跨候选）或 user-level training（跨样本）摊销用户侧计算。
- **整体含义**：HELIX 试图给出一个"**纯化且统一**"的范式——统一（交错而非两阶段）但纯化（不含 LHUC、DCN-M、FM 模块、跨层残差、辅助损失等额外组件），在保持用户侧计算可复用的同时，让两条轴可**非对称、灵活**地扩展。

## 2. 方法论

### 2.1 核心思想

- 任务设定：对用户 u 与候选视频 c 预测 ŷ_{u,c} = f_Θ(x_c, s_u, s^{u×c})，其中 x_c 为非序列特征，s_u 为**候选无关的 U-only 序列**（同一请求内所有候选共享），s^{u×c} 为**候选条件序列**（如 hard/soft search 相似度序列）。
- **关键设计：单向信息流**。信息只能从用户侧序列流向候选侧 mix-token，绝不反向。由此 U-only 序列的 K/V 缓存可在同一请求的所有候选间（serving）以及同一用户的所有样本间（training）复用。
- **交错而非合并**：注意力负责"序列检索"，token-wise FFN 负责"特征交互"，二者在同一骨干中反复交替，保留跨深度通信。

### 2.2 三流 Tokenization

- **MixTokenizer**：将所有非序列特征 embedding 与每条序列的均值池化摘要 `ē_s = MeanPool(E_s)` 做 **All-Concat**，再经 **Auto-Split** 切成 M 个定宽组（末组补零），每组用独立参数的 LayerNorm 与前馈投影生成一个 mix-token。采用 **per-token LayerNorm**（而非 RMSNorm），因其可学习偏置 β 类比 FAT 的 field-aware bias；这是全模型唯一的 LayerNorm，其余归一化均为 RMSNorm。
- **SeqTokenizer**：U-only 与 U×C 两条序列流分别经投影 W_s 映射到统一维度 d_s，**位置编码在拼接前逐序列独立施加**（避免跨序列类型强加全局相对顺序）。若干可学习 **[SINK] token** 前置作为注意力汇（attention sink）。

### 2.3 MixFormer（候选侧）

- 每块两个残差子层：**CrossAttn → Mixup-PerToken-FFN (MPTF)**。
- 公式化流程：X̂ = X + CrossAttn(RMSNorm(X), S^{u×c})；X^{ℓ+1} = X̂ + MPTF(RMSNorm(X̂))。最后一块**不做输出归一化**（交给 Decoder 的输入归一化）。
- **注意力细节**：QK-Norm + GQA + 门控注意力（gate 施加在 **value 投影之后**，即 Ṽ = V ⊙ σ(G)）；query 投影按 mix-token 分别参数化以保留异构性，序列侧 K/V/G 为位置级共享。
- **MPTF**：简化版 TokenMixer。将每个 token 的 d_m 通道切成 M 段，第 t 个输出 token 收集所有输入 token 的第 t 段（参数无关的 Mixup），再经 SwiGLU 的 token-wise FFN：`[SiLU(x̃_t W^g_t) ⊙ (x̃_t W^u_t)] W^d_t`。用显式跨 token 通信替代二次复杂度的自注意力，同时保留特征组异构性。

### 2.4 SeqFormer

- **Encoder（U-only → 可复用 K/V 缓存）**：每块为 self-attention + position-wise FFN（共享 FFN，因 U-only token 较同质）。
  - **金字塔查询压缩**：按预定义压缩调度 L₀ ≥ L₁ ≥ … ≥ L_{N_E−1} = L_c。首块用 **Gather** 按特征重要性分析给定的**逐序列预算 k_s** 抽取各序列最近 k_s 个有效状态拼成单一 query 流；后续块用 **Truncate** 保留递减前缀。保留状态作 query 与残差主分支，但**始终对当前层全部有效状态做 K/V**，从而在被裁掉前先吸收其信息。
  - 末块省略 SDPA、输出投影与 FFN，只做 K/V 投影与 value 门控，产出缓存 C_u = (M_u, K_u, Ṽ_u)。
- **Decoder（候选侧）**：结构与 MixFormer 镜像，只是把 U×C 序列换成可复用缓存：Ẑ = Z + A_cache(RMSNorm(Z), K_u, Ṽ_u; M_u)；Z^{r+1} = Ẑ + MPTF(RMSNorm(Ẑ))。
  - 采用 **lazy K/V**：只投影 query，缓存 K/V 不再投影；随着 Z 逐层精化，高层 query 可从同一缓存检索更丰富模式。
  - 最终 RMSNorm + mean pooling → 任务塔。

### 2.5 训练与推理优化

- **变长执行**：Encoder 入口一次性去 padding 并打包全部有效状态（N_v = Σℓ_b，而非 B·L_max），全程不物化 padding；该路径禁用 XLA 以避免反复重编译，改用融合变长 kernel，注意力使用 FA4 变长接口；缓存输出再 pad 回静态形状供候选侧使用。
- **摊销分析（Amdahl 形式）**：设 C_M、C_E、C_D 为三类块成本，n 个候选独立计算为 n(C_M+C_E+C_D)，复用缓存为 C_E + n(C_M+C_D)，加速比 = 1 / [(1−p) + p/n]，其中 p = C_E/(C_M+C_E+C_D)。**p = 0.95、n = 100 时理论上限约 16.8×**。
- **M-FALCON（serving）**：候选 query 直接在注意力 kernel 内映射到共享缓存，避免按候选物化缓存造成的 HBM 读写。
- **User-level Training（training）**：同用户 J 个样本只评估一次 U-only encoder。

## 6. 主要结论与发现

- **整体效果**：HELIX-L（358M / 35.28G）在 CTR 与 CVR 上全面超过基线：相对 RankMixer + Transformer 基线 CTR ΔAUC +0.21%、ΔUAUC +0.82%，CVR ΔAUC +0.17%、ΔUAUC +1.38%；在**更少参数与 FLOPs** 下超过 OneTrans（+0.15%/+0.10%）。
- **缩放律**：随计算量增加，CTR/CVR AUC 平滑提升且**在最大配置（XXL，130.24G）仍未饱和**；拟合为幂律 `log(ΔAUC) = 0.085·log C − 4.733`（CTR）与 `0.132·log C − 5.749`（CVR）。RankMixer 在低 FLOPs 有竞争力但随规模落后，OneTrans 在更大算力下仍不及 HELIX-L，说明**架构设计决定算力转化为效果的效率**。
- **关键设计验证**：
  - MPTF 优于自注意力（+0.05% CTR / +0.02% CVR），说明自注意力不适配高度异构特征 token；
  - 仅从 K/V 缓存做交叉注意力（排除 mix-token 自注意力）更优（+0.02%/+0.02%），避免 mix-token 自我关注分散行为检索；
  - **末层 K/V 缓存**效果与逐层缓存相当，但**解耦了两轴的深度**，支持向可摊销的序列分支非对称倾斜；
  - 非参数 Gate-Up-Norm 缓解 SwiGLU 与逐 token 参数化带来的激活爆炸（替代 SoftCap），使激活落入 FP16/BF16 高精度区间；

- **算力信息缺失**：未披露 GPU 型号、数量、训练时长与集群规模，削弱了可复现性与缩放律研究的可比较性。

## 8. 对领域的启示与总结

- **范式层面**：HELIX 提出"**统一但纯化**"的设计哲学——把特征交互与序列建模放进同一骨干反复交错，同时剔除一切额外组件，并强制**单向信息流**以保留用户侧计算的跨候选、跨样本摊销能力。这为"如何联合扩展推荐模型的两条建模轴"提供了一个清晰且可操作的答案。
- **架构层面**：三项设计具有迁移价值——
  1. **用 MPTF 替代自注意力做特征交互**：显式跨 token 通信 + 保留特征组异构性，规避二次复杂度，呼应 TokenMixer 的发现；
  2. **末层 K/V 缓存**：将序列分支与候选分支的深度**解耦**，使两轴可非对称扩展，是摊销友好架构的关键；
  3. **金字塔查询压缩 + 全量 K/V**：在裁剪 query 的同时仍对全部有效状态做注意力，兼顾效率与信息完整性。
- **工程层面**：变长打包执行、FA4 变长接口、M-FALCON、user-level training 等优化，展示了摊销设计从理论到落地的完整路径。
- **缩放律层面**：幂律拟合（CTR 指数 0.085、CVR 指数 0.132）在最大配置仍未饱和，提示**联合扩展两轴可获得更有利的 scaling slope**，为后续更大规模探索提供了经验证据。

**总体判断**：HELIX 是一篇工程导向明确、设计逻辑自洽的工业推荐架构论文，在统一建模、摊销效率与缩放行为三方面贡献清晰。其主要短板在于**外部有效性、效率实测与统计严谨性**，未来工作若能补充公开数据集验证、端到端延迟数据与显著性检验，将显著增强其说服力。
