## Abstract 

Generative query suggestion, powered by Large Language Models (LLMs), has become increasingly popular in search and conversa-tional systems to reduce user friction and guide intent formulation. Existing approaches align suggestions with user preferences (e.g., clicks or conversions). This works for open-ended applications like chatbots and personal assistants, where the result space is uncon-strained or historical user free-text queries are abundant. However, applying these methods to travel search presents two limitations. First, travel search is fundamentally constrained by physical inventory; a query (e.g., “romantic beachfront villa”) may yield abundant results in Bali but few in Tokyo, so aligning with user preferences is not by itself grounded in what can be offered. Second, travel platforms traditionally rely on faceted search interfaces with no free-text queries. This creates a cold-start problem: without historical query logs there is no demand-side data for alignment, and without a seed query at request time, suggestions must be generated proactively from structured context alone. To address these challenges, we propose SCOUT, a bootstrapping framework for supply-aware proactive query suggestion. SCOUT overcomes the data gap by substituting missing demand-side user feedback with supply-side system feedback. It treats the search engine as a reinforcement learning environment, deriving a dense reward from the production reranker’s query-listing match scores, and optimizes the policy with Group Relative Policy Optimization (GRPO). SCOUT improves inventory match rate (IMR@18) by 12.3% while preserving diversity, matching a compute-intensive best-of-8 policy at zero marginal inference cost and making supply-aware suggestion deployable on a real-time travel search path.

## 1 Introduction 

Search systems are undergoing a fundamental paradigm shift, evolv-ing from rigid keyword matching and faceted filtering toward fluid, natural language interfaces. In this context, Generative Query Sug-gestion, powered by Large Language Models (LLMs), has emerged as a powerful tool to reduce user friction and proactively guide search intent formulation. State-of-the-art approaches for aligning these generative models heavily rely on Supervised Fine-Tuning (SFT) and Reinforcement Learning from Human Feedback (RLHF) [2, 8, 18]. However, these standard methodologies implicitly assume the avail-ability of massive demand-side datasets, specifically historical free-text queries and user click-through logs. Applying these standard alignment techniques to travel search introduces two challenges. First is a critical cold-start data gap. Historically, travel platforms have relied on highly structured UI elements, requiring users to input destinations, travel dates, and guest counts via calendars and dropdowns. Consequently, there is an absence of historical free-text query logs to serve as training data. Second, travel search operates under strict physical inventory constraints. Unlike open-domain search where any linguistically coherent response is valid, a travel query suggestion sets an expecta-tion of physical inventory. Generating an appealing but unfulfillable query (e.g., suggesting a “romantic beachfront villa” in a landlocked city) leads to empty search result pages, degrading user experience. Models without supply-awareness actively hallucinate demand. Naive approaches to supply-aware generation fail to meet pro-duction requirements. Simple template-based generation reads as rigid and robotic, lacking the ability to synthesize fluidly with spe-cific travel contexts. Inventory-conditioned prompting is also a non-starter, as a compact, latency-friendly summary of available in-ventory for arbitrary travel search does not exist at generation time. A serving-time best-of-𝑁 strategy—generating multiple candidate suggestions and querying the live search engine to serve the ones with highest inventory—solves the inventory problem but creates a system bottleneck. Issuing 𝑁 heavy search requests per interaction introduces latency and computational costs that are prohibitive for a real-time travel search engine. To bridge the gap between generative intent and physical inventory—without historical user data or serve-time latency and cost penalties—our core insight is to substitute missing demand-side user feedback with supply-side system feedback. ## 2 Problem Setting & Related Work 

The Travel Search Setting. Travel platforms have historically relied on structured, faceted search interfaces (date pickers, des-tination autocomplete) rather than an open text box. Introducing free-text search therefore starts from a setting with two properties that, together, are unique among the domains where generative query suggestion has been studied (Table 1). First, there is no user-authored free-text query: not as input at request time, and not in historical logs. Second, travel search is bounded by physical, location-specific inventory. These two properties are what rule out the two established families of prior work. 

Gap 1: Alignment Requires Demand-Side Data. Large Lan-guage Models have shifted the query suggestion space toward gen-erative query suggestion, where supervised fine-tuning and RLHF align suggestions with user intent using historical free-text queries and engagement feedback [2, 4, 8, 18]. These methods assume the demand-side data that our setting does not have. 

Gap 2: Retrieval Feedback Requires a Seed Query. A second family uses the retrieval system as the reward source, optimizing query reformulation, rewriting, or expansion against retrieval out-comes [1, 6, 9, 10, 17, 19]. While we share the intuition of using the search engine as an RL environment, these existing methods are fundamentally reactive transformations . They rely on a user-authored seed query as a reference anchor, optimizing how well the rewrite preserves and expands that existing intent. In contrast, our task is proactive generation . Because the free-text query is strictly the output rather than the input, we have no reference intent to anchor the reward. Instead of preserving intent, our model must

## 3 Methodology 

To tackle the absence of demand-side data and the physical con-straints of travel search, we introduce a supply-aware framework for generative query suggestion. First, we establish a scalable, label-free evaluation suite to objectively measure inventory and diversity (§3.1). Second, we utilize the live search engine for supply-side feedback, training the policy via online RL (§3.2). 

## 3.1 Evaluation without Demand-Side Data 

Two axes: inventory and diversity. Click-through and conver-sion are unavailable during bootstrapping. To overcome this, we walk backward from the ideal guest experience to define proxy cri-teria for success. A suggestion sets an expectation about the page behind it, which gives the first axis, inventory : clicking must open results that match the suggestion, not an empty or low inventory page. The second axis is diversity , both a UX necessity to prevent repetitive slates and a crucial guardrail against diversity collapse, a documented failure mode of preference optimization [13, 14].

## 3.2 SCOUT: Supply-Aware Optimization via Online RL 

The Search Engine as a Reward Environment. The best-of-𝑁 

policy of §1 can guarantee supply-backed suggestions, but it pays for that guarantee at every impression: 𝑁 search calls per slate, none of which leave the underlying model any more supply-aware. The cost recurs indefinitely because the knowledge stays outside the model. SCOUT instead pays it once, at training time, by treating the live search stack as a reinforcement learning environment and amortizing inventory validation into the policy weights. To achieve this without historical demand-side data, we formu-late query generation as a reinforcement learning problem where the live search engine acts as the environment (Figure 2). The LLM agent observes a state 𝑐 (the parameterized travel context, such as destination and dates) and takes an action by generating a slate of query suggestions 𝑆 . These suggestions are executed against the environment (the search engine), which retrieves physical inven-tory and returns a reward based on the semantic quality of those listings, driving the policy update.

The Limits of Prompting and SFT: The Few-shot baseline achieves strong diversity (84.03 distinct%@0.9) but yields only mod-est inventory grounding. This asymmetry defines the problem for every trained arm: raise inventory-awareness, hold diversity. Prompting struggles because the model inherently lacks access to the dynamic inventory of a given market. RSFT attempts to close this gap by learning from best-of-𝑁 generations, but yields only marginal gains (+1.75% IMR@18) because RSFT only copies winning samples: it never observes a good-versus-bad contrast, and remains constrained by the frozen Few-shot policy’s output distribution. 

The Diversity Collapse in Preference Learning: DPO ex-plicitly learns from contrastive pairs, but we observe a severe di-versity collapse (11.07 distinct%@0.9). The model concentrates its distribution on a narrow set of generic queries due to likelihood displacement [13, 14]. RPO mitigates this by anchoring the model with an auxiliary SFT loss. ## 4.3 Amortizing Serve-Time Search into Model Weights 

Figure 3 places these gains against the alternative of validating inventory at serve time. Best-of-𝑁 buys inventory-awareness with search calls; each call is a full search request issued on every impres-sion, so the cost recurs for the lifetime of the feature. SCOUT pays it once during training instead: it reaches 0 .32 with no search calls of its own, marginally above best-of-8 and 81% of the way from best-of-1 to best-of-16. This is what makes supply-aware query generation deployable on a real-time travel search path. 

## 5 Conclusion and Ongoing Work 

We introduced SCOUT, a framework for generating supply-aware query suggestions to bootstrap natural language interfaces. As a short paper on ongoing work, our limitations and future roadmap are best understood through a two-phase deployment strategy: 

Phase 1: System Capability Bootstrapping (Current). 

SCOUT explicitly tackles the cold-start problem by aligning LLMs with supply-side constraints. Consequently, our current limitations include a reliance on offline evaluation metrics and a reward signal that scores fulfillability but not appeal. However, this pure supply-aware bootstrapping is a necessary precondition; it ensures the initial system is reliable and functional enough to launch, which is required to collect meaningful user interaction data. 

Phase 2: Demand-Aware Alignment (Ongoing). An ideal query suggestion system must synthesize both supply availabil-ity and demand preferences. As the interface rolls out, our ongo-ing work focuses on large-scale online A/B testing to capture live demand-side signals (e.g., click-through rates, booking conversions). This data will drive our transition from pure supply-awareness to a balanced, multi-objective alignment strategy, ensuring future suggestions are physically fulfillable and resonant with user intent.
