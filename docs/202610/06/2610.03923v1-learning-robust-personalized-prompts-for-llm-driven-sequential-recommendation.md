## 摘要
LLM驱动的序列推荐将下一项预测建模为以自然语言提示为条件的自回归生成。然而，语义等价提示中细微的措辞变化就可能导致性能大幅波动，损害鲁棒性，并需要昂贵的人工提示工程。连续提示学习降低了对模板的依赖，但面临两个相互作用的挑战：共享的任务级指令缺乏用户特定的推理引导，而梯度更新可能将连续提示推出LLM的有效语义空间。注入个性化信号会进一步放大这种语义漂移。为应对这些挑战，我们提出LRPRec，一种可学习的提示框架，它从离散模板初始化连续指令提示，并引入两种互补机制。个性化提示注入将用户行为编码为偏好嵌入，并以加性方式注入共享提示，从而实现参数高效的用户级适配。语义漂移约束将共享提示正则化到其初始化锚点附近的信任域内，以在优化过程中保持语义有效性。通过约束共享组件并允许加性个性化，LRPRec将稳定性与表达力解耦。在三个基准数据集上的大量实验表明，LRPRec在持续优于强基线方法的同时，免除了对背景模板和任务推理模板进行人工调参的需要。

## Abstract
LLM-driven sequential recommendation formulates next-item prediction as autoregressive generation conditioned on natural-language prompts. However, minor wording changes in semantically equivalent prompts can cause substantial performance fluctuations, undermining robustness and requiring costly manual prompt engineering. Continuous prompt learning reduces template dependence but faces two interacting challenges: shared task-level instructions lack user-specific reasoning guidance, while gradient updates can push continuous prompts outside the LLM's effective semantic space. Injecting personalized signals can further amplify this semantic drift. To address these challenges, we propose LRPRec, a learnable prompting framework that initializes continuous instruction prompts from discrete templates and introduces two complementary mechanisms. Personalized prompt injection encodes user behavior into a preference embedding and additively injects it into shared prompts, enabling parameter-efficient user-level adaptation. A semantic drift constraint regularizes the shared prompts within a trust region around their initialization anchors to preserve semantic validity during optimization. By constraining the shared component while allowing additive personalization, LRPRec decouples stability from expressiveness. Extensive experiments on three benchmark datasets demonstrate consistent improvements over strong baselines while eliminating the need for manual tuning of background and task inference templates.

- **核心痛点**：现有方法高度依赖离散自然语言提示模板，且对提示措辞极其敏感。语义等价但措辞、语序、标点略有差异的提示，可能导致推荐性能显著波动，造成鲁棒性差、复现困难，并带来高昂的人工提示工程成本。
- **连续提示的潜力与挑战**：连续提示学习用可学习向量替代离散模板，可降低模板依赖，但直接用于推荐存在两个相互纠缠的问题：
  - **缺乏个性化**：现有连续提示多为所有用户共享的任务级指令，无法提供用户特定的推理引导。
  - **语义漂移**：梯度更新可能把连续提示推出 LLM 可有效解释的语义空间；注入用户特定信号会进一步放大漂移风险。
- **论文含义**：作者提出 **LRPRec**，目标是在 LLM 驱动序列推荐中实现鲁棒、个性化、参数高效的可学习提示，既消除对背景与任务推断模板的人工调参，又保持生成有效性。

## 2. 方法论
### 核心思想
- 将提示显式分解为 **指令部分** 与 **证据部分**：
  - 指令：背景提示 `X_bg`、任务提示 `X_task`，实例不变，是提示敏感性的主要来源。
  - 证据：交互序列 `X_seq`、候选池 `X_cand`，由原始输入序列化得到，保持不变。
- 用连续可学习向量 `P_bg` 和 `P_task` 替代离散指令模板，并从离散模板的 token embedding 初始化。
- 通过 **个性化提示注入** 实现用户级适配，通过 **语义漂移约束** 保持共享提示在 LLM 有效语义空间内。
- 关键设计：漂移约束只作用于共享提示，个性化以加性方式注入，从而解耦稳定性与表达力。

### 关键技术细节
- **提示参数化**：
  - `P_bg = {p_bg_1, ..., p_bg_M}`，`P_task = {p_task_1, ..., p_task_N}`，维度与 LLM 输入 token embedding 相同。
  - 默认背景模板 token 数为 `M=12`，任务模板 token 数为 `N=26`。
- **模板初始化**：从手写离散模板的 token embedding 初始化连续提示。随机初始化实验完全失败，说明提示必须位于 LLM 有效语义空间。
- **用户偏好摘要**：
  - 构造偏好 elicitation prompt，让冻结 LLM 总结用户交互历史。
  - 提取 `<user_preference>` 特殊 token 在最后一层 Transformer 的隐藏状态 `z_u`，作为高层用户偏好表示。
  - 训练时离线预计算并缓存 `z_u`，不向 LLM 反传梯度。
- **偏好投影与加性注入**：
  - 用轻量线性层投影：`e_u = W_p z_u + b_p`。
  - 将 `e_u` 加到每个共享提示向量上：`p̃_bg_i = p_bg_i + e_u`，`p̃_task_j = p_task_j + e_u`。
  - 最终输入为 `[P̃_bg_u; P̃_task_u; X_seq_u; X_cand_u]`。
  - 该设计不增加输入长度，只增加一个 `d×d` 投影矩阵和偏置，参数开销小。
- **语义漂移约束**：
  - 定义初始化 embedding 为固定语义锚点 `A_bg`、`A_task`。
  - 采用 hinge-style 正则：若提示向量偏离锚点超过半径 `ε`，则施加线性惩罚。
  - 总损失：`L = L_rec + α · L_drift`。
  - 只约束共享提示 `P_bg`、`P_task`，不约束 `e_u`。理由：`e_u` 来自冻结 LLM 的隐藏状态，本身位于模型语义空间，且是数据依赖的个性化信号，约束它会抑制个性化。
- **两阶段训练**：
  - **Stage 1 推荐适配**：用 LoRA 在推荐任务上微调 backbone LLM，使用离散提示模板，让模型获得推荐领域知识。
  - **Stage 2 提示优化**：加载 Stage 1 checkpoint，冻结全部 LLM 参数，只训练 `P_bg`、`P_task`、`W_p`、`b_p`。
- **推理**：
  - 固定学习到的提示和投影参数。
  - 对用户序列计算 `z_u` 与 `e_u`，注入共享提示，拼接序列化证据，LLM 解码得到预测，再映射回候选池。
  - `z_u` 可缓存，仅当用户序列更新时需重新前向计算；推理无需人工调背景与任务模板。

## 6. 主要结论与发现
- LRPRec 在 MovieLens、Steam、LastFM 上均取得最佳 VHR@1：
  - MovieLens：`0.4947`，ValidRatio `1.0000`。
  - Steam：`0.5412`，ValidRatio `1.0000`。
  - LastFM：`0.5016`，ValidRatio `1.0000`。
- 个性化提示注入显著提升推荐精度；去掉个性化后性能一致下降，但 ValidRatio 仍高，说明个性化主要贡献精度而非输出有效性。
